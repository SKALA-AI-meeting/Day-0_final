# 의도 분류 지침

지원자가 토론방에 쓴 메시지 하나를 읽고 의도와 대상 안을 분류한다. 결과는 토론 진행(안별 지지 누적, 화자 선택, 칸 채움 조건)에만 쓰이고 평가 수준을 정하지 않는다. 의도가 분명하지 않으면 `confidence`를 `low`로 둔다. 틀린 high보다 low가 낫다.

## 입력 블록

- `[메시지]`: 분류할 지원자 메시지
- `[단계]`: 메시지가 쓰인 단계(`keyword`·`problem`·`solution`·`proposal`). 현재 단계가 아니라 이 단계 기준으로 분류한다
- `[카탈로그 안]`: 그 단계의 시나리오 안 전체 `[{scenario_option_key, label}]`(아직 아무도 말하지 않은 안 포함, 키워드 단계는 후보 4개)
- `[나온 안]`: 이미 생긴 안 `[{option_id, label, scenario_option_key}]`
- `[직전 메시지]`: 앞 메시지 5개(보낸 사람 표시)
- `[참여자]`: 자리 id와 표시 이름

## wanted (먼저 쓴다)

다른 칸을 정하기 전에 `wanted`에 지원자가 이 메시지에서 원하거나 내놓은 안을 지원자 말로 20자 이내로 적는다("~로 가요", "제 표는 ~", "~가 끌려요", "~하는 방식은 어떨까요?" 같은 제안 포함). 원하는 안 없이 보류·반대·질문만 하면 null이다. `wanted`는 분류를 돕는 칸이고 저장하지 않는다.

## 의도

아래 예에서 A안·B안·C안은 그 단계의 안 자리를 뜻하는 표시이고, 실제 입력에서는 `[카탈로그 안]`·`[나온 안]`의 라벨로 바꿔 읽는다.

| intent | 뜻 | 예 |
|---|---|---|
| `propose` | 새 안 또는 기존 안을 자기 의견으로 낸다(다른 안을 보류·반대하면서 내도 `propose`) | "저는 A안으로 가면 좋겠어요" |
| `agree` | 다른 사람이 낸 안에 동의한다 | "OO님 말대로 B안이 낫겠네요" |
| `oppose` | 특정 안에 반대한다 | "C안은 범위가 너무 넓어서 별로예요" |
| `withhold` | 원하는 안을 밝히지 않은 채 어떤 안을 보류·유보하거나 판단을 미룬다(기권 포함) | "A안은 일단 미뤄 둘게요", "아직 고르지 않을게요" |
| `question` | 질문한다(근거·의견 요청 포함) | "OO님은 어느 쪽이 좋으세요?" |
| `other` | 위에 해당하지 않음(인사·호응·진행 말) | "네네", "다음은 뭐 하면 돼요?" |

의도는 아래 순서로 정한다. 앞 단계에서 정해지면 뒤 단계는 보지 않는다.

1. **`wanted`가 있는가(지원자가 지금 원하는 안이 하나라도 있는가).** "제 표는 ~", "~가 좋아요", "~로 가요", "~가 더 끌려요", "~하는 방식은 어떨까요?"처럼 지원자가 어떤 안(새 아이디어 포함)을 원하거나 내놓으면 그 안이 대상이고, 지원자가 처음 낸 안이면 `propose`, 다른 사람이 낸 안에 따르면 `agree`다. 같은 메시지에서 **다른** 안을 보류·반대·걱정해도 의도는 바뀌지 않는다("A안 말고 B안으로 가요", "A안은 보류고 제 표는 C안이에요", "A안은 미뤄 두고 저는 이런 방식을 해 보고 싶어요"). 보류·반대한 안은 대상이 아니다.
2. `wanted`가 null이고 어떤 안을 보류·유보하거나 판단을 미루면 `withhold`다. 장점을 인정하거나 질문을 덧붙여도 `withhold`다("장점은 알겠는데 아직 고르진 못하겠어요", "그 안은 미뤄 두고 더 얘기해 봐요"). 보류를 `propose`·`agree`로 바꾸지 않는다.
3. `wanted`가 null이고 반대만 있으면 `oppose`다.
4. 질문만 있으면 `question`이다. 앞선 말이 지지가 아니었다고 바로잡는 말은 그 안을 대상으로 한 `propose`·`agree`가 아니다.

### 양보가 섞인 말

"좋긴 한데", "일리는 있는데", "괜찮긴 한데" 같은 양보 표현 자체는 의도를 정하지 않는다. 양보 뒤에 지원자가 **어디에 서는지**로 정한다.

| 메시지가 끝나는 자리 | intent | reservation |
|---|---|---|
| 그 안을 고른다("그래도 그걸로 가요") | `agree`(남의 안)·`propose`(자기 안) | `false` |
| 그 안을 고르되 걱정·조건을 붙인다("비용만 맞으면요") | `agree`·`propose` | `true` |
| 고르지 않는다: 걱정·의문만 붙이거나 미룬다·보류한다("아직 정하진 않을게요", "~가 걱정이에요") | `withhold` | `true` |
| 다른 안을 고른다("그래도 저는 다른 쪽이요") | 그 다른 안에 `agree`·`propose` | 그 다른 안 기준 |

짝 예시(같은 양보, 다른 끝):

- "B안 좋긴 한데, 그래도 B안으로 가요" → `agree` B안, reservation false.
- "B안 좋긴 한데 운영 인력이 걱정이에요" → `withhold` B안, reservation true(고르지 않고 걱정만 붙임).
- "B안으로 가요. 운영 인력은 걱정이지만요" → `agree` B안, reservation true(고르면서 걱정을 붙임).
- "B안 좋긴 한데 아직 정하진 않을게요" → `withhold` B안, reservation true(고르지 않고 미룸).
- "B안 좋긴 한데 저는 C안이 더 끌려요" → `propose`·`agree` C안(누가 먼저 냈는지에 따라), reservation false(B안은 대상이 아님).

## 대상 안

- `target`: 대상이 `[나온 안]`에 있으면 그 `option_id`, 아직 행이 없는 카탈로그 안이면 그 `scenario_option_key`. 새 안이거나 대상이 없으면 null.
- `new_option_label`: `propose`인데 같은 안이 없을 때만 20자 이내 짧은 라벨, 아니면 null. `target`과 함께 채우지 않는다.

`propose`의 대상은 이렇게 정한다.

1. 지원자가 낸 아이디어가 **무엇을, 누구에게, 어떤 방법으로** 하는지 떠올린다.
2. `[나온 안]`·`[카탈로그 안]` 라벨과 하나씩 견준다. 라벨의 핵심 명사구를 그대로 쓰거나 라벨이 말하는 일·방법을 다른 말로 말하면 그 안이다. 같은 분야 낱말(문자, 경보, 알림, 주민, 시설 등)만 겹치고 하는 일이 다르면 같은 안이 아니다.
   - 예: 카탈로그에 `골목 야간 조명 확충`이 있고 메시지 "밤에 골목이 너무 어두워서 가로등을 더 달면 좋겠어요" → 같은 일을 다른 말로 말했으므로 그 안.
   - 예: 카탈로그에 `주민 신고 앱으로 파손 시설 접수`가 있고 메시지 "주민 참여로 벽화를 그리는 건 어때요?" → '주민'만 겹치고 하는 일이 다르므로 새 안.
3. 같은 안이 없으면 새 안이다. `[카탈로그 안]`은 미리 정해 둔 안 목록일 뿐이다. 아직 아무도 말하지 않은 카탈로그 안이 남아 있어도 새 아이디어를 거기에 넣지 않는다.

## confidence

- `high`: 의도와 대상이 둘 다 분명하다.
- `low`: 농담·반어, 대상이 둘 이상이거나 불분명, "그것도 괜찮고요" 같은 애매한 호응, 조건부("만약 ~면 ~도 괜찮을 듯").

## reservation

`target`·`new_option_label`로 정한 **대상 안 하나만** 본다. 지원자가 그 안을 고르거나 지지하면서 그 안에 망설임·조건·걱정·보류를 붙였으면 `true`, 아니면 `false`다("~로 가요, 비용은 걱정이지만", "~라면 괜찮아요"). 같은 메시지에 다른 안에 대한 반대·보류·걱정이 있어도 대상 안에 붙은 것이 아니면 `false`다. 예: "A안은 보류고 제 표는 C안이에요" → 대상 C안, `false`. "A안 말고 B안으로 가요" → 대상 B안, `false`. "A안이나 B안은 비용이 걱정이고 저는 이런 방식을 생각했어요" → 대상은 새 방식, `false`. `withhold`·`oppose`는 `true`다.

## addressed_to와 excluded

- `addressed_to`: 이름을 부르거나 직전 발언에 답한 자리 id 목록. 전체에게 묻는 질문이면 `[]`.
- `excluded`: 지원자가 이번에는 답하지 말라고 뺀 동료(이름으로 부른 사람)의 자리 id 목록("OO님 말고 XX님 생각은요?"의 OO님). 안 번호(1번·2번·3번)는 자리가 아니다. 없으면 `[]`. `excluded`에 넣은 자리는 `addressed_to`에 넣지 않는다.

## 출력

JSON 하나만 낸다. 다른 글은 쓰지 않는다.

```json
{"wanted": "골목 조명", "intent": "propose", "new_option_label": null, "target": "x_p2", "confidence": "high", "reservation": false, "addressed_to": [], "excluded": []}
```

## 예시

예시는 실제 시나리오가 아닌 가상의 카탈로그를 쓴다. 참여자는 `p1` 가온, `p2` 나래, `p3` 다온이고, 단계 problem의 카탈로그 안은 `x_p1`(통학로 불법 주정차), `x_p2`(골목 야간 조명 부족), `x_p3`(공원 쓰레기 무단 투기), 단계 solution의 카탈로그 안은 `x_s1`(단속 카메라·데이터 연계), `x_s2`(주민 순찰 봉사단), `x_s3`(골목 야간 조명 확충)이다. `reservation`·`excluded`를 적지 않은 예는 `false`·`[]`다. `wanted`는 적지 않았다.

- 단계 problem, 메시지 "저는 골목이 어두운 게 더 큰 문제라고 봐요" → `propose`, `target: x_p2`, high, `[]`.
- 직전에 다온이 `x_s2`를 밀었고 메시지 "다온님 말 듣고 보니 순찰 봉사단도 괜찮네요" → `agree`, 대상 `x_s2`(나온 안이면 id), high, `["p3"]`.
- 메시지 "가온님, 주정차는 이미 단속하고 있어서 새롭지 않은 것 같아요" → `oppose`, 대상 `x_p1`, high, reservation true, `["p1"]`.
- 메시지 "조명 쪽은 판단을 조금 미룰게요. 자료를 더 보고 싶어요" → `withhold`, 대상 `x_p2`, high, reservation true.
- 메시지 "순찰 봉사단이 끌리긴 하는데 아직 고르진 못하겠어요" → `withhold`, 대상 `x_s2`, high, reservation true.
- 메시지 "단속 카메라 좋은데 설치비가 걱정이에요" → 고르지 않았으므로 `withhold`, 대상 `x_s1`, high, reservation true.
- 메시지 "단속 카메라로 가요. 설치비는 걱정이지만요" → `agree`, 대상 `x_s1`, high, reservation true.
- 메시지 "주정차 말고 쓰레기 쪽으로 가요" → `propose`, 대상 `x_p3`, high, reservation false.
- 메시지 "나래님은 해결책 뭐가 좋다고 보세요?" → `question`, 대상 없음, high, `["p2"]`.
- 메시지 "다온님 말고 나래님은 어떻게 보세요?" → `question`, 대상 없음, high, addressed_to `["p2"]`, excluded `["p3"]`.
- 메시지 "다들 어느 쪽이 좋으세요?" → `question`, 대상 없음, high, `[]`.
- 메시지 "음 둘 다 나쁘지 않은데…" → `other`, 대상 없음, low, `[]`.
- 메시지 "차라리 통학 버스 노선 문제로 하면 어때요?" → `propose`, `new_option_label: "통학 버스 노선"`, high, `[]`.
- 단계 problem, 메시지 "주정차는 미뤄 두고 공원 소음을 다뤄 보고 싶어요" → 공원 소음을 고르므로 `propose`, `new_option_label: "공원 소음"`, high, reservation false(주정차는 대상이 아님).
- 단계 solution, 메시지 "학교에서 안전 지도 그리기 수업을 하면 어때요?" → 순찰 봉사단과 대상·방법이 달라 `propose`, `new_option_label: "학교 안전 지도 수업"`, high.
- 메시지 "1번은 보류고 제 표는 3번이에요"(나온 안 순서가 `x_s1`·`x_s2`·`x_s3`) → `propose`·`agree` 대상 `x_s3`, high, reservation false(1번은 대상이 아님).
