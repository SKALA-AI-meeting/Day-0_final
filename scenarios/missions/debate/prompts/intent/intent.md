# 의도 분류 지침

지원자가 토론방에 쓴 메시지 하나를 읽고 의도와 대상 안을 분류한다. 결과는 토론 진행(안별 지지 누적, 화자 선택, 칸 채움 조건)에만 쓰이고 평가 수준을 정하지 않는다. 의도가 분명하지 않으면 `confidence`를 `low`로 둔다. 틀린 high보다 low가 낫다.

## 입력 블록

- `[메시지]`: 분류할 지원자 메시지
- `[단계]`: 메시지가 쓰인 단계(`keyword`·`problem`·`solution`·`proposal`). 현재 단계가 아니라 이 단계 기준으로 분류한다
- `[카탈로그 안]`: 그 단계의 시나리오 안 전체 `[{scenario_option_key, label}]`(아직 아무도 말하지 않은 안 포함, 키워드 단계는 후보 4개)
- `[나온 안]`: 이미 생긴 안 `[{option_id, label, scenario_option_key}]`
- `[직전 메시지]`: 앞 메시지 5개(보낸 사람 표시)
- `[참여자]`: 자리 id와 표시 이름

## wanted (먼저 쓴다)

다른 칸을 정하기 전에 `wanted`에 지원자가 이 메시지에서 원하거나 내놓은 안을 지원자 말로 20자 이내로 적는다("~로 가요", "제 표는 ~", "~가 끌려요", "~하는 방식은 어떨까요?" 같은 제안 포함). 원하는 안 없이 보류·반대·질문만 하면 null이다. `wanted`는 분류를 돕는 칸이고 저장하지 않는다.

## 의도

| intent | 뜻 | 예 |
|---|---|---|
| `propose` | 새 안 또는 기존 안을 자기 의견으로 낸다(다른 안을 보류·반대하면서 내도 `propose`) | "저는 침수 문제로 가면 좋겠어요" |
| `agree` | 다른 사람이 낸 안에 동의한다 | "지안님 말대로 S2가 낫겠네요" |
| `oppose` | 특정 안에 반대한다 | "가뭄은 너무 흔한 주제라 별로예요" |
| `withhold` | 원하는 안을 밝히지 않은 채 어떤 안을 보류·유보하거나 판단을 미룬다(기권 포함) | "침수 쪽은 일단 보류할게요", "아직 고르지 않을게요" |
| `question` | 질문한다(근거·의견 요청 포함) | "하람님은 어떻게 생각하세요?" |
| `other` | 위에 해당하지 않음(인사·호응·진행 말) | "네네", "시간 얼마나 남았죠?" |

의도는 아래 순서로 정한다. 앞 단계에서 정해지면 뒤 단계는 보지 않는다.

1. **`wanted`가 있는가(지원자가 지금 원하는 안이 하나라도 있는가).** "제 표는 ~", "~가 좋아요", "~로 가요", "~가 더 끌려요", "~하는 방식은 어떨까요?"처럼 지원자가 어떤 안(새 아이디어 포함)을 원하거나 내놓으면 그 안이 대상이고, 지원자가 처음 낸 안이면 `propose`, 다른 사람이 낸 안에 따르면 `agree`다. 같은 메시지에서 **다른** 안을 보류·반대·걱정해도 의도는 바뀌지 않는다("나무 말고 바람으로 가요", "2번은 보류고 제 표는 3번이에요", "가뭄은 미뤄 두고 지하수 오염을 다뤄 보고 싶어요", "그 안은 보류예요. 대신 ~하는 방식은 어떨까요?"). 보류·반대한 안은 대상이 아니다.
2. `wanted`가 null이고 어떤 안을 보류·유보하거나 판단을 미루면 `withhold`다. 장점을 인정하거나 질문을 덧붙여도 `withhold`다("장점은 알겠는데 아직 고르진 못하겠어요", "그 안은 미뤄 두고 더 얘기해 봐요"). 보류를 `propose`·`agree`로 바꾸지 않는다.
3. `wanted`가 null이고 반대만 있으면 `oppose`다.
4. 질문만 있으면 `question`이다. 앞선 말이 지지가 아니었다고 바로잡는 말은 그 안을 대상으로 한 `propose`·`agree`가 아니다.

## 대상 안

- `target`: 대상이 `[나온 안]`에 있으면 그 `option_id`, 아직 행이 없는 카탈로그 안이면 그 `scenario_option_key`. 새 안이거나 대상이 없으면 null.
- `new_option_label`: `propose`인데 같은 안이 없을 때만 20자 이내 짧은 라벨, 아니면 null. `target`과 함께 채우지 않는다.

`propose`의 대상은 이렇게 정한다.

1. 지원자가 낸 아이디어가 **무엇을, 누구에게, 어떤 방법으로** 하는지 떠올린다.
2. `[나온 안]`·`[카탈로그 안]` 라벨과 하나씩 견준다. 라벨의 핵심 명사구를 그대로 쓰거나 라벨이 말하는 일·방법을 다른 말로 말하면 그 안이다(예: "킥보드 배터리 불이 걱정이에요" → `전동킥보드·배터리 화재`). 같은 분야 낱말(문자, 경보, 알림, 주민, 시설 등)만 겹치고 하는 일이 다르면 같은 안이 아니다(예: "소방차 진입로 불법 주차를 단속하는 앱" ≠ `IoT 화재 감지·알림 데이터`).
3. 같은 안이 없으면 새 안이다. `[카탈로그 안]`은 미리 정해 둔 안 목록일 뿐이다. 아직 아무도 말하지 않은 카탈로그 안이 남아 있어도 새 아이디어를 거기에 넣지 않는다.

## confidence

- `high`: 의도와 대상이 둘 다 분명하다.
- `low`: 농담·반어, 대상이 둘 이상이거나 불분명, "그것도 괜찮고요" 같은 애매한 호응, 조건부("만약 ~면 ~도 괜찮을 듯").

## reservation

`target`·`new_option_label`로 정한 **대상 안 하나만** 본다. 지원자가 그 안을 고르거나 지지하면서 그 안에 망설임·조건·걱정·보류를 붙였으면 `true`, 아니면 `false`다("~ 좋은데 비용이 걱정이에요", "~라면 괜찮아요"). 같은 메시지에 다른 안에 대한 반대·보류·걱정이 있어도 대상 안에 붙은 것이 아니면 `false`다. 예: "2번은 보류고 제 표는 3번이에요" → 대상 3번, `false`. "나무 말고 바람으로 가요" → 대상 바람, `false`. "센서나 보상은 비용이 걱정이고 저는 ~ 방식을 생각했어요" → 대상은 새 방식, `false`. `withhold`·`oppose`는 `true`다.

## addressed_to와 excluded

- `addressed_to`: 이름을 부르거나 직전 발언에 답한 자리 id 목록. 전체에게 묻는 질문이면 `[]`.
- `excluded`: 지원자가 이번에는 답하지 말라고 뺀 동료(이름으로 부른 사람)의 자리 id 목록("지안님 말고 하람님 생각은요?"의 지안님). 안 번호(1번·2번·3번)는 자리가 아니다. 없으면 `[]`. `excluded`에 넣은 자리는 `addressed_to`에 넣지 않는다.

## 출력

JSON 하나만 낸다. 다른 글은 쓰지 않는다.

```json
{"wanted": "침수 피해 문제", "intent": "propose", "new_option_label": null, "target": "water_p2", "confidence": "high", "reservation": false, "addressed_to": [], "excluded": []}
```

## 예시

`reservation`·`excluded`를 적지 않은 예는 `false`·`[]`다. `wanted`는 적지 않았다.

- 단계 problem, 카탈로그에 `water_p2`(도심 폭우·침수 피해 증가), 메시지 "저는 침수 피해 쪽이 더 크다고 봐요" → `propose`, `target: water_p2`, high, `[]`.
- 직전에 서지안이 S2를 밀었고 메시지 "지안님 말 듣고 보니 절수 보상도 괜찮네요" → `agree`, 대상 S2(나온 안이면 id), high, `["p3"]`.
- 메시지 "한결님, 가뭄은 매년 있는 거라 새롭지 않은 것 같아요" → `oppose`, 대상 P1, high, reservation true, `["p1"]`.
- 메시지 "침수 안은 판단을 조금 미룰게요. 자료를 더 보고 싶어요" → `withhold`, 대상 P2, high, reservation true.
- 메시지 "나무가 끌리긴 하는데 아직 고르진 못하겠어요" → `withhold`, 대상 나무, high, reservation true.
- 메시지 "센서 경보 좋은데 설치비가 걱정이에요" → `agree`, 대상 S1, high, reservation true.
- 메시지 "나무 말고 바람으로 가요" → `propose`, 대상 바람, high, reservation false.
- 메시지 "하람님은 해결책 뭐가 좋다고 보세요?" → `question`, 대상 없음, high, `["p2"]`.
- 메시지 "지안님 말고 하람님은 어떻게 보세요?" → `question`, 대상 없음, high, addressed_to `["p2"]`, excluded `["p3"]`.
- 메시지 "다들 어떻게 생각하세요?" → `question`, 대상 없음, high, `[]`.
- 메시지 "음 둘 다 괜찮은데…" → `other`, 대상 없음, low, `[]`.
- 메시지 "차라리 학교 급식 문제로 하면 어때요?" → `propose`, `new_option_label: "학교 급식 문제"`, high, `[]`.
- 단계 problem, 메시지 "가뭄은 미뤄 두고 지하수 오염을 다뤄 보고 싶어요" → 지하수 오염을 고르므로 `propose`, `new_option_label: "지하수 오염"`, high, reservation false(가뭄은 대상이 아님).
- 카탈로그에 `water_s2`(주민 절수·보상 캠페인)가 있고 메시지 "학교에서 물 절약 수업을 하면 어때요?" → 대상과 방법이 달라 `propose`, `new_option_label: "학교 물 절약 수업"`, high.
