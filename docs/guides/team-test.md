# 팀원 시연 테스트 가이드

내 컴퓨터에서 실제 AI 동료와 실제 Azure 음성으로 음성 토론을 해 보고 의견을 남기는 방법이다. 명령은 저장소 루트에서 실행한다. 프로필 설명은 [infra/profiles/README.md](../../infra/profiles/README.md), 설정은 [configuration.md](configuration.md)를 본다.

## 1. 준비

- 코드: 처음이면 `git clone`, 이미 있으면 `git checkout main && git pull`.
- 설치: Docker Desktop(실행 중이어야 함), Chrome, `git`, `make`, `python3`(macOS는 기본 포함). 서비스는 모두 컨테이너에서 돌아 `uv`·`pnpm`은 필요 없다.
- `infra/.env`: 키를 관리하는 팀원에게 안전한 채널(1:1 메시지 등)로 받아 `infra/.env`에 둔다. 이 파일은 커밋하지 않고 채팅방·이슈·스크린샷에도 올리지 않는다. 키가 노출되면 바로 그 팀원에게 알린다.

## 2. 처음이 아니면: DB 볼륨 다시 만들기

postgres는 볼륨이 비어 있을 때만 `infra/db/schema.sql`을 적용한다. 그래서 예전에 `make up`을 해 본 사람은 볼륨에 옛 스키마가 남아 있어 API가 뜨지 않을 수 있으니 볼륨을 지운다. **로컬 DB의 데이터(채용 건·세션·리포트)가 모두 사라진다.** 남기고 싶으면 스택이 떠 있을 때 먼저 백업한다.

```
docker compose -f infra/docker-compose.yml --env-file infra/.env exec -T postgres pg_dump -U dayzero -Fc dayzero > backup.dump
```

그다음 지운다. 처음 받은 사람은 건너뛴다. 자세한 설명은 [database.md](database.md).

```
make down PROFILE=dev-real
docker volume rm infra_pgdata
```

## 3. 실행

```
make doctor PROFILE=dev-real                                      # 조합과 키 존재 검사(외부 호출 없음)
make up PROFILE=dev-real ALLOW_API=1                              # 처음엔 이미지 빌드로 몇 분 걸린다
make seed PROFILE=dev-real SEED_ARGS="--minutes 15"               # 관리자 계정·채용 건(15분) 만들기
```

`make doctor`에서 `없음`이 보이면 `infra/.env`가 덜 채워진 것이니 키를 관리하는 팀원에게 묻는다.

지원자 링크 얻기:

1. `http://localhost:3000/admin/login`에서 시드 기본 관리자 계정으로 로그인한다. 이메일과 비밀번호 기본값은 `scripts/seed.py`의 `--email`·`--password` 인자 기본값이다. 비밀번호는 문서에 적지 않으니 그 파일을 본다.
2. 채용 건(서비스기획 신입)에서 `초대 링크 만들기`를 눌러 링크를 만든다.
3. 그 링크를 **같은 컴퓨터의 Chrome**에서 열고, 마이크 권한을 `허용`한다. macOS는 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 Chrome도 켜져 있어야 한다. 이어폰을 쓰면 AI 소리가 마이크로 다시 들어가지 않는다.

## 4. Azure 음성은 한 번에 한 명

무료(F0) 음성 자원을 팀이 같이 쓰므로 동시에 세션 하나만 가능하다. 시작 전에 팀 채널에 시간과 이름을 남기고, 끝나면 끝났다고 남긴다.

세션을 시작할 때 `음성 시연은 한 번에 한 세션만 진행합니다`가 나오면 다른 사람이 세션 중이다. 채널을 확인하고 끝난 뒤 다시 시작한다. 사용량은 매달(UTC) 새 원장으로 센다. 한도가 부족하다는 안내가 나오면 키를 관리하는 팀원에게 알린다.

## 5. 테스트 체크리스트

한 번 끝까지(키워드 → 문제 → 해결 → 기획안) 해 보며 아래를 본다.

- [ ] 내 차례와 AI 차례가 구분되어 언제 말할지 알 수 있다.
- [ ] 일반·손들기·강제 차례 모두 [발언하기]를 눌러 말을 시작한다. 동료가 말하는 중에 손을 들면 지금 발언이 끝난 뒤 내 차례가 온다.
- [ ] 받아 적은 글은 내 화면에 보이지 않고 그대로 전달된다. 끝난 뒤 관리자 화면 전체 기록에서 내 말과 맞는지 본다. 특히 이름 `한결`·`하람`·`지안`이 제대로 적혔는지 보고 틀린 낱말을 메모해 둔다.
- [ ] 말하는 사람이 큰 칸에 보이고, 동료 발언 자막이 소리와 맞게 나오며 끝나면 방금 한 말만 남는다.
- [ ] 카드 장면이 단계에 맞게 나온다.
- [ ] 결정한 칸이 화면에 채워진다.
- [ ] 기획안 편집기에서 쓰고 제출된다.
- [ ] 마무리 화면(debrief)이 나온다.
- [ ] 관리자 화면 리포트에 행동 근거와 수준이 나온다(점수·합격 표현이 없어야 한다).
- [ ] [발언 완료]를 누른 뒤 다음 동료 목소리가 나오기까지 걸린 시간을 대략 적는다(예: 약 3초, 10초 이상).

## 6. 의견 남기기

GitHub 이슈를 새로 열고(라벨 제안: `playtest`, 필요하면 `voice`·`bug`) 아래 틀을 채운다. 이미 모아 두는 추적 이슈가 있으면 거기에 댓글로 같은 틀을 붙여도 된다. 키·비밀번호·개인정보는 쓰지 않는다.

```
화면/단계: (예: 해결책 단계, 기획안 편집기)
무엇을 했는지:
기대:
실제:
받아 적기 지연/오인식 낱말(있으면):
스크린샷: (붙여넣기)
```

## 7. 끝나면

```
make down PROFILE=dev-real
```

팀 채널에 끝났다고 남긴다.
