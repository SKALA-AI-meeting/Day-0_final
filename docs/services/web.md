# web (Next.js)

음성 토론의 상태·전사·오류·비용은 [음성 구현](../architecture/voice.md)을 따른다.

지원자·관리자 화면의 구현 구조다. 화면 흐름과 화면 규칙은 [product/user-flows.md](../product/user-flows.md), 토큰·컴포넌트·라이브러리·모션은 [architecture/design-system.md](../architecture/design-system.md), 실행 명령은 `apps/web/README.md`. Next.js App Router + Tailwind. 상태 관리는 React 상태와 fetch로 충분하다. UI 라이브러리는 [architecture/design-system.md](../architecture/design-system.md)의 "라이브러리" 표에 있는 것만 쓴다.

## 구조

```
apps/web/
  app/                  라우트: /admin/*(login·signup·positions·sessions·sample-report), /s/[token], /api/health
  components/debate/    지원자 화면(candidate-flow·debate-view·chat·decision-panel·side-panels·proposal-editor·debrief-screen·link-screens), reducer·use-session·saver
  components/admin/     관리자 화면(채용 건·지원자 목록·리포트·전체 기록·검토)
  components/ui/        공용 컴포넌트(디자인 시스템)
  components/dev/       mock 조작 패널(NEXT_PUBLIC_MOCK=1에서만)
  lib/api.ts, lib/ws.ts REST 래퍼(ApiError)와 WS 연결·재연결
  mocks/                계약 예시 JSON 사본과 WS 재생 대본(NEXT_PUBLIC_MOCK=1)
  fixtures/             샘플 리포트(sample-report.json)
  e2e/                  Playwright 단계별 화면 테스트(stages/)와 mock 캡처 스크립트
```

- 상태는 React 상태와 fetch로 다룬다. `/state` 스냅샷이 전체 상태이고 WS 프레임은 증분이다(`seq`가 비면 `/state` 재조회).
- `NEXT_PUBLIC_API_URL`·`NEXT_PUBLIC_WS_URL`·`NEXT_PUBLIC_MOCK`은 **빌드 시점**에 번들에 들어간다(`apps/web/Dockerfile` ARG). 컨테이너 런타임 env만 바꿔서는 바뀌지 않으므로 이미지를 다시 빌드한다. 값이 없으면 `http://localhost:8000`·`ws://localhost:8000`(`lib/api.ts`). 실행 모드별 값은 [guides/configuration.md](../guides/configuration.md).

## 이름의 정본

- API·WS 이름은 [contracts/README.md](../contracts/README.md), 요소·카드·차원·기록 없음 사유 이름은 [product/rubric.md](../product/rubric.md)·[product/scenario.md](../product/scenario.md)가 정본이고, 이 문서의 이름이 정본과 다르면 정본이 맞다. 칸 결과 필드는 `resolution: consensus | timeout`, 채운 사람은 `filled_by: candidate | p1 | p2 | p3 | system`이다(시간 초과는 `system`이고 결정 사항에 "정한 사람" 줄을 쓰지 않는다).

## 화면 검증 항목

관리자 상단 바에는 채용 건·샘플 리포트 메뉴가 있다. 채용 건 생성은 이름·세션 길이를 한 화면에서 입력하며 체크포인트가 현재 입력 위치를 나타낸다. 리포트 목차는 스크롤 위치를 따라가고 개요에 수준을 매긴 세부 행동·근거로 쓴 서로 다른 기록·근거 약함·발동한 카드 장면의 개수를 표시한다. 세션 흐름 띠는 칸 확정·카드 장면·접속 끊김을 시간 위치에 놓는다. 요소별 세부 행동에는 수준 점과 근거 2개 및 더 보기가 있고, 참고 기록은 키보드 화살표로 이동하는 탭으로 전환한다. 인쇄 미리보기와 실제 인쇄에서는 접힌 근거를 펼치고 참고 기록 세 패널을 제목과 함께 모두 보여 준다. 전체 기록은 필터 뒤 남은 기록을 기준으로 현재 단계를 따라가는 체크포인트와 타임라인이다. 지원자 입장·동의·대기·디브리핑은 상단 진행 체크포인트를 공유하며, 동의 화면에서는 다섯 항목을 모두 확인해야 동의 체크박스를 쓸 수 있다. 대기 화면에는 단계 시간표가 나온다.

- 지원자 전 화면·전 상태가 mock으로 돈다: 입장(만료·취소·완료 링크), 동의 화면의 형식 안내·어시스턴트 문구·다섯 항목 순차 확인 뒤 동의 체크박스 활성화·표시 이름 입력(기본값 입장 응답의 초대 이름)과 그 이름이 토론방·AI 동료 호칭에 쓰임, 동의 전 시작 불가, 대기 화면 레이아웃 그림과 시작 전 `/state`로 그린 이름만 보이는 팀 소개, 토론 세션, 디브리핑(첫 문장·이의 제기 경로·카드 설명·내 발언 2~3개·성향 공개·기획안 열람·설문 2문항+자유 의견·문의), 재연결과 `seq` 누락 시 `/state` 복원.
- 지원자 화면 용어: "칸"·"합의 패널"·"확정"이 지원자 화면 문구에 없고 "정할 항목"·"결정 사항"·"이걸로 정하기"를 쓴다.
- 토론 세션: 상단 4단계 진행바와 단계 남은 시간(로컬 카운트다운·`timer` 보정·2분 전 warning), 남은 시간과 오피스 시각이 한 줄에 함께 나오지 않음. 음성 모드(기본)의 토론 화면 구성은 [`apps/web/README.md`](../../apps/web/README.md) "토론 화면 배치와 음성 회의"가 정본이다. 프로필 이미지는 비율이 다른 임시 파일에서도 원형 고정 크기로 보이고, 깨진 URL이면 이니셜로 대체. 말풍선·입력 중 표시·`message.ack` 확정 표시는 테스트 텍스트 모드(`VOICE_ENABLED=0`)에서만 쓴다.
- 우측 4탭: 결정 사항에 결과 줄만(후보안·지지 현황·오피스 시각 없음), 현재 항목만 입력·[이걸로 정하기], `slot.confirmed` timeout 결과 표시(적용 규칙별 시스템 안내)와 입력 값 잠김; 입력 중 typing 5초 갱신; 자료 잠김 → `materials.opened`로 열림 → Markdown 뷰어; 어시스턴트 요청·인용·복사·한도 안내; 기획안 6칸 디바운스 저장, `idea_credit` 중립 안내 한 줄, 토론 단계 제출 비활성, 제출 확인 창 → 잠김 → [나가기] → 디브리핑, 자동 제출 한 줄.
- 페르소나 유형이 **디브리핑 전** 지원자 화면과 응답에 없다: 디브리핑 컴포넌트·`debrief*.json`을 뺀 지원자 컴포넌트와 지원자 mock(`entry*`·`state_*`·`debate_script`·`materials`·`material`·`assistant_response`·`proposal*`)에서 `stubborn|quiet|critic|agreeable|divergent` grep 0건. 디브리핑은 성향 공개가 정상이다.
- 관리자: 생성 화면은 이름·세션 길이(60·15)·요소 안내(읽기 전용, 선택 UI 없음)·샘플 리포트 링크, 링크 재발급과 재응시 초대가 구분된 행 액션, 지원자 목록 상태 묶음·요소별 수준 칩·low 차원 수(합계·정렬 없음)·실패 안내·삭제 예정일.
- 리포트 draft가 mock으로: 머리의 "설계된 장면" 안내와 카드 칩, 요약표의 요소 "수준 N (1~5)"·서술(합계 없음), 타임라인(칸 결과·지지 현황·최초 제안자·카드 발동), 요소 섹션의 차원별 수준·확신도·판단 이유·근거, low 차원의 "근거 약함, 원문 확인 권장", 근거 클릭 시 원문·앞뒤 맥락, 맥락 참조 구분, 기록 없음의 상태 칩(장면 없음·반응 없음·판단 보류)과 사유 6종 문장·요약표 상태별 개수·선결정 카드 표시, 머리의 용어 설명과 화면 용어 "세부 행동"(평가 문장 속 "차원"도 바꿔 보임), 기여 대조표, 사실 지표, 제출 기획안, 시간순 AI 활용. 차원 단위 조정(메모 없으면 저장 불가)과 요소 수준 재계산·"담당자 조정됨"·검토 완료 확인 창(`reviewer_name` 포함, 422 표시)·final 메모 추가. "기록에서 보기"가 기록 화면의 해당 줄을 하이라이트. 인쇄 미리보기에서 차원 전부 펼침. 화면·mock 어디에도 총점·합계·점수 표기가 없다.
- 디자인: 라이트·다크 둘 다 동작, 말풍선·본문 대비 4.5:1 이상([architecture/design-system.md](../architecture/design-system.md) 대비 표), 이름이 항상 보여 색 없이도 화자 구분 가능, [design-system.md](../architecture/design-system.md) "하지 않는 것" 목록 없음, 그림자는 떠 있는 요소에만.
- 행동 유도 문구 없음, 보드·분업·파트 문서·팀장·개인 알림 흔적 없음: 지원자 컴포넌트·mock에서 `board.tsx|BoardColumn|division|my-docs|my_document|doc-viewer|manager|notices.test|office_script|slot.filled` grep 0건. 현행 이름 `SystemNotice`·`entry_notice`·`scoring_notice`·`retention_notice`와 "대시보드" 같은 일반 단어는 검사 대상이 아니다.
- `review-animations`·`break-ui` 통과.

같은 항목을 실제 api(`NEXT_PUBLIC_MOCK=0`)에서는 단계별 화면 테스트(`make e2e SUITE=stages PROFILE=test-text`, 가짜 LLM)로 확인한다([guides/testing.md](../guides/testing.md) "단계별 테스트").
