# 로컬 LLM 전환 계획 (베이스 하나 + 역할 어댑터)

**상태: 계획(미구현).** 이 문서는 현재 동작이 아니라 바꿀 방향을 적는다. 구현되면 해당 내용을 [harness.md](harness.md)·[agents.md](agents.md)로 옮기고 이 문서는 지운다. 구조 변경 기록은 `D22/prefixcon.md` PC-23.

## 0. 배경

외부 API 의존은 LLM 다섯 역할뿐이다(음성은 Whisper·Supertonic, 임베딩은 bge-m3로 이미 로컬). 2026-10-25 Ollama에서 하네스의 실제 의도 분류 코드(`app.agent.intent.classify`)와 `tests/eval/intent_cases.yaml` 20문장으로 잰 값:

| 모델 | 의도 정확도 | 폴백 | 도구 호출(3문항) | 의도 p50 |
|---|---|---|---|---|
| gpt-4o-mini (기준선, harness.md) | 0.85 | — | 정상 | 1.0초 |
| EXAONE 4.0 1.2B Q4_K_M | 0.30 | 14/20 | 0/3 | 1.3초 |
| EXAONE 4.0 1.2B BF16 | 0.25 | 19/20 | 0/3 | 2.6초 |
| qwen:4b | 0.30 | 17/20 | 미지원(400) | 7.1초 |

출력 형식은 문제가 아니었다(Ollama의 `json_schema` 강제는 동작). 판단 내용이 틀렸고, 1.2B는 도구를 한 번도 부르지 않았으며, 페르소나 시험에서는 역할을 무시하고 긴 일반 답변을 썼다. 결론: 프롬프트만으로는 안 되고 (1) LLM 입출력을 좁히는 하네스 변경과 (2) 역할별 SFT 어댑터가 필요하다. 시험 스크립트(`exaone_probe.py`)는 P1에서 `tests/eval/`로 옮긴다.

## 1. 원칙

1. **외부 전송 0.** 세션 중·평가 중 외부 호출이 없다. 학습 데이터 생성 단계만 예외이며 3.4에서 따로 정한다.
2. **베이스 모델 하나 + 역할 어댑터.** 메모리에 베이스 하나만 올리고 요청마다 LoRA 어댑터를 고른다. 역할이 바뀌어도 말투·지식의 바탕이 같아 멀티턴이 안정된다.
3. **결정은 코드, 말투만 LLM.** 지금도 누가 말할지·어떤 안을 밀지·합의·시간 초과·칸 채우기는 결정적 코드다(AGENTS.md 고정 제약). LLM이 판단하던 나머지도 입력에 사실로 넣어, 모델은 "주어진 상황을 성향대로 한두 문장으로 말하기"만 한다.
4. **다양성의 범위를 명시한다.** 바뀌는 축(4장)만 데이터로 덮고, 형식·길이·금지 표현은 고정해 코드가 검사한다.

## 2. 역할 배치

| 역할(env) | 지금 | 바꾼 뒤 | 어댑터 |
|---|---|---|---|
| 의도 분류 `MODEL_INTENT` | 4o-mini, json_schema | 같은 입출력, 로컬 | `intent` |
| 입장 판정 `judge_stance` (의도 분류 모델 사용) | 4o-mini | 같은 입출력, 로컬 | `intent`(과제 태그로 같이 학습) |
| 진행 매니저 `MODEL_TURN` | 규칙 + 규칙으로 안 정해질 때만 LLM | **규칙만**. 노드는 유지 | 없음(1차) |
| 페르소나 `MODEL_PERSONA` | 4o-mini + 도구(조회·검색) | **도구 없음**, 구조화 입력 → `{content, proposes, stance}` | `persona` 하나(성향은 입력) |
| 어시스턴트 `MODEL_ASSISTANT` | 4o-mini + 도구 루프(최대 3회) | 검색은 코드, 모델은 **1회 호출로 답 + 인용** | `assistant` |
| 평가 `MODEL_EVALUATOR` | 4o-mini, 요소당 1호출(세션 전체) | **2차로 미룸.** 큰 로컬 모델 또는 별도 어댑터를 따로 검증 | (미정) |

- 턴 LLM 제거: 지금도 실패 시 기본 응답 자리 규칙으로 넘어가므로 규칙만으로 동작은 정의돼 있다. 지명 응답률 등이 떨어지는지는 `persona_eval`로 확인하고, 떨어지면 P2 뒤에 `turn` 어댑터를 추가한다.
- 페르소나 어댑터를 하나로 두는 이유: 성향(고집형·소극형·비판형)별로 나누면 데이터가 3분의 1로 줄고 한국어 대화 능력을 공유하지 못한다. 성향 카드(`persona_<type>.md` 요약)를 매 요청 입력에 넣어 조건으로 쓴다.

## 3. 하네스 변경

### 3.1 페르소나 입출력 고정

입력은 지금 `persona/__init__.py`가 만드는 블록을 그대로 쓰되, 도구로 가져오던 것을 미리 넣고 길이를 줄인다.

| 블록 | 지금 | 바꾼 뒤 |
|---|---|---|
| `[성향]` | `persona_<type>.md` 전문 | 요약 카드(말투·행동 규칙·must_not 핵심 6~10줄) |
| 공통 규칙 | `common_rules.md` 전문 | 어댑터가 학습으로 갖고, 입력에는 금지 목록 한 줄만 |
| `[상황]` | `situation_text` | 그대로(이미 사실 문장) |
| `[내 입장]` | stance_plan 사실 | 그대로 |
| `[카드 차례]` | 해당 자리만 | 그대로 |
| `[내 기억]` | 내 최근 발언 3개 | 그대로 |
| 지지 현황·확정 칸·남은 시간 | 미리 넣은 DebateState | 그대로 |
| 최근 대화 | 30개 | **10~12개**(1.2B 문맥·지연 고려, P2에서 측정해 정함) |
| 자료 | 도구 `search_materials`·`get_material` | **코드가 `load`에서 rag-mcp를 직접 호출**해 넣는다. 쿼리는 답할 메시지 + 단계, top 3, 합계 2k자 |
| 기획안 초안 | 도구 `get_draft`(proposal 단계) | proposal 단계 `load`가 넣는다 |
| 앞 대화 | 도구 `get_transcript` | 뺀다(최근 대화로 충분) |

출력은 지금과 같은 `{content, proposes?, stance?}`(1~2문장, 200자 권장). 출력 뒤 guard → stance_check → 반복 검사 → 400자 상한은 그대로다.

### 3.2 어시스턴트

코드가 rag-mcp `search_materials`(top 3)로 자료를 찾고, 모델은 질문 + 자료 조각을 받아 답과 인용 번호를 한 번에 쓴다. 숫자 검사(자료에 없는 숫자 → 재생성 1회 → 문장 제거)와 쓴 자료만 인용 규칙은 그대로다. 요청 예산은 7회에서 1~2회로 준다.

### 3.3 평가표 필수 요소와의 관계 (유지 확인)

- State·Graph 에이전트(진행 매니저 + 페르소나 3): 그래프 노드 9개 유지. turn 노드는 규칙만으로 돈다.
- MCP 3개: debate-mcp·rag-mcp·assessment-mcp 유지. 페르소나가 도구로 부르던 rag-mcp는 `load` 노드(코드)가 부른다. 페르소나의 assessment-mcp 차단(허용 목록 + 토큰)은 그대로다.
- 하네스 8요소: Tools의 "페르소나 도구 3회"가 "load 사전 조회"로, Agent Loop의 어시스턴트 도구 루프가 단일 호출로 바뀐다. 나머지 요소는 그대로다.
- 공정성: 어댑터는 프롬프트와 같은 지위로 본다. 채용 건 생성 때 `positions.scenario`에 `llm: {base, base_sha, adapters: {intent, persona, assistant}: sha}`를 복사해 고정하고, 세션 실행·평가는 그 버전만 쓴다. 고정된 버전이 서버에 없으면 409 `position_outdated`(지금의 복사본 누락 규칙과 같다).

### 3.4 키 규칙·서빙

- 키 규칙(`roles.py` 외 사본 3곳): 모델 id에 `local/` 접두사 규칙을 추가한다(예: `local/exaone-4.0-1.2b+persona@<sha>`). 이 규칙의 모델은 키 없이 `LOCAL_LLM_URL`(OpenAI 호환)로 가고, 어댑터 이름을 요청 본문에 넣는다. 기존 gpt·gemini 규칙은 남긴다. 대체 모델은 지금처럼 없다.
- 서빙: llama.cpp `llama-server`(베이스 GGUF 하나 + LoRA GGUF 여러 개를 시작 때 올리고 요청마다 고름, OpenAI 호환 `/v1/chat/completions`, `json_schema`·문법 강제 지원). Ollama는 어댑터마다 모델을 따로 만들어야 해서 쓰지 않는다. GPU 서버로 옮기면 vLLM multi-LoRA.
- 메모리(2026-10-25 실측 기준): 베이스 Q4 약 0.8GB(BF16 2.6GB) + 어댑터 각 수십 MB + KV 캐시(동시 세션 수 × 문맥). Whisper 1.15GB(최대 1.9GB)·Supertonic 0.5GB·bge-m3 1.1GB와 합쳐 Docker 7.75GB 안에 들어간다.
- 학습 데이터 생성 시 외부 호출: 교사 모델이 OpenAI면 출력 사용 조건(약관)을 먼저 확인한다. 기본안은 로컬 대형 모델(7~32B) 교사.

## 4. SFT 데이터

### 4.1 공통

- **입력은 실제 코드로 만든다.** `tests/eval/persona_eval.py`의 `agent_harness()`(실 그래프 + 가짜 MCP·hub)로 시나리오를 돌려, 진짜 `load`·`cards`·`turn`·`stance_plan`이 만든 상황 블록을 저장한다. 손으로 만든 입력과 실제 입력의 어긋남을 없앤다.
- **지원자 발언 공급원**: (1) `tests/eval/virtual_candidate`(scripted·autonomous) 대본, (2) 교사가 성향별 지원자 페르소나로 생성, (3) 음성 받아 적기 잡음 변형(띄어쓰기·조사 오류·동음이의, 실제 Whisper 출력에서 오류 패턴을 뽑아 적용).
- **필터**(저장소의 검사기를 그대로 사용): guard 패턴(`shared/guard_patterns.yaml`), stance_check 판정, 반복 유사도 0.8, 길이 상한, 의도 일관성(교사 정답을 교사로 재분류해 다르면 버림), 금지어(합격·순위·점수 등).
- **중복 제거**: 정규화 문자열 유사도 0.9 이상은 하나만.
- **사람 검토**: 어댑터마다 무작위 5%. 성향 말투·호칭("OO님")·존댓말 확인.
- **분할**: 시나리오 시드 단위로 train/valid를 나눈다(같은 세션의 턴이 양쪽에 섞이지 않게).
- **평가 세트와 분리**: `intent_cases.yaml`·`intent_holdout_cases.yaml`·`persona_scripts.yaml`·`leak_cases.yaml`의 문장·세션은 학습에 넣지 않고, 생성 단계에서 문자열 유사도로 걸러 낸다(과거 평가 문장이 프롬프트 예시에 들어가 0.95로 부풀었던 사례, harness.md).

### 4.2 `intent` 어댑터

- 과제 태그: `<task:intent>`, `<task:stance>`. 출력은 기존 스키마 그대로(`intent.SCHEMA`, `judge_stance` 출력).
- 다양성 축: 단계 4 × 기존 안 유무 × 의도 5종 + 보류·유보·정정·"A 말고 B"·새 안·이름 부르기·자리 빼기 × 받아 적기 잡음.
- 목표 규모: intent 3~5천, stance 1~2천.

### 4.3 `persona` 어댑터

- 다양성 축: 성향 3 × 단계 4 × 상황(답하기·지명 응답·침묵 초대·카드 전달(카드 6장의 장면 목적)·압박 회차·설득 이동 직후·반대/보류 누적) × 내 입장 상태(밝힘 전/후, 이동 가능 여부) × 지원자 발화 의도 5종 × 자료 유무.
- 고정: 1~2문장, 존댓말, "OO님" 호칭, 시간은 단계 남은 시간으로만, 성향 이름·평가·결론 대리 금지, JSON 출력.
- 멀티턴 안정성 항목(반드시 포함): 같은 세션의 연속 턴(최소 6턴) 묶음, 내 기억과 겹치지 않는 새 근거, 상대 말 오인용 금지, 입장 유지·이동이 `[내 입장]`과 일치.
- 목표 규모: 8천~1만5천 턴(성향별 균형).

### 4.4 `assistant` 어댑터

- 다양성 축: 자료 근거 질문, 자료 밖 질문(모른다고 답함), 숫자 질문, 요약 요청, 길이 제한.
- 고정: 인용 번호, 자료에 없는 숫자 금지.
- 목표 규모: 2~3천.

## 5. 학습

- 도구: MLX(`mlx-lm`) 4비트 베이스 위 LoRA(Apple Silicon, CUDA 없음). 어댑터는 llama.cpp `convert_lora_to_gguf.py`로 GGUF LoRA로 바꾼다.
- 시작 설정(검증 전 초기값): rank 16, alpha 32, dropout 0.05, lr 1e-4, 2~3 epoch, 최대 길이 2048, 대상 attention·MLP 투영.
- 베이스: 1순위 EXAONE 4.0 1.2B. P1·P2 통과 기준 미달이면 2.4B로 올린다. **라이선스가 비상업(NC)** 이라 연구용으로만 쓴다(상업 운영이면 베이스를 바꾼다).
- 재현성: 데이터 생성 시드·교사 모델·필터 버전·학습 설정을 어댑터 sha와 함께 기록하고, 실행 기록(`agent_runs.usage.model`, `evaluation_runs.model`)에 어댑터 sha를 남긴다.
