# 음성 토론 구현

현재 구현의 기준이다. [최초 턴 설계](voice-turns.md)와 [후보·비용 비교](voice-services.md)는 설계 근거이며 아래 구현 범위를 우선 확인한다.

## 실행 경계

`app/voice/controller.py`는 DB의 `voice_states`·`speech_jobs`를 읽어 AI_GENERATING → AI_SPEAKING → USER_READY → USER_SPEAKING → TRANSCRIBING → PROCESSING을 관리한다. 기존 LangGraph·의도 분류·화자 선택·페르소나·guard·stance_check·합의는 유지한다. TTS는 저장된 최종 메시지만 받는다. 합의·시간 초과 고정 공지도 음성 항목에 포함한다.

브라우저는 `/voice`를 750ms 간격으로 조회한다. 활성 run이 모두 끝나고 모든 TTS 항목이 준비된 뒤 저장 순서로 하나씩 재생한다. `play()` 성공이나 생성 완료를 청취 완료로 간주하지 않는다. 첫 미완료 항목의 `start`와 실제 `ended` 확인을 저장해야 다음 항목으로 넘어간다. AI 발언이 0개면 바로 USER_READY다. 재생 오류는 발언권을 열지 않고 재시도 안내를 표시한다.

기존 메시지·관리자 기록·디브리핑 근거는 남고 토론방의 말풍선·입력창은 회의 화면으로 대체된다. 말하는 동료 카드 아래에 현재 재생 중인 문장을 자막으로 보인다. 접을 수 있는 최근 발언에는 이미 들은 동료 발언과 지원자가 제출한 발언만 최대 10개 보이며, 미재생 동료 발언은 먼저 보여 주지 않는다. 결정 사항(기획안 단계는 기획안)은 오른쪽 위, 자료·AI 어시스턴트 탭은 오른쪽 아래에 고정하고, 왼쪽에는 메모장과 단계 안내를 둔다.

가운데 칸은 4명 프로필(2x2)이 칸을 가득 채우고 바로 아래에 조작부가 붙는다. 조작부 첫 줄은 지금 상태를 말한다: 첫 음성 상태를 받기 전에는 "회의 상태를 불러오는 중…"과 자리표시, 연결이 끊겨 다시 잇는 중이면 끊김 표시, 동료 차례에는 "강한결님이 말하는 중"처럼 말하는(준비하는) 동료 이름, 녹음 중에는 "● 녹음 중 0:12 / 1:00"이다. 녹음 중에는 음량 파형과 테두리가 굵은 큰 [발언 완료]가 보이고 내 프로필이 음량만큼 빛난다. 내 차례 유지 시간(일반 차례 `turn_hold_seconds`, 손들기·강제 차례는 자동 녹음까지)은 큰 숫자와 줄어드는 막대로 보이고, 글을 쓰는 곳이나 버튼에 포커스가 없으면 Space로 [발언하기]를 누를 수 있다. 진행을 막는 오류는 경고 아이콘·짧은 제목·할 일 문장과 바로 아래 그 일을 하는 버튼 하나(다시 보내기·다시 재생·다시 받아 적기·다시 녹음·다시 연결)로 보이고, 진행을 막지 않는 안내는 회색 한 줄로 6초 뒤 사라진다. 다시 시도 횟수(`voice_retry_exhausted`)를 다 쓰면 버튼 없이 "다음 차례에 말해 주세요"를 보인다. 녹음 중 연결이 끊겼다 이어지면 "끊긴 동안의 발언은 저장되지 않았어요. 다시 말해 주세요"를 보인다. 동료 음성 재생 중 지원자 마이크 음량으로 끼어들기를 알리는 기능은 없다(동료 차례에는 마이크를 열지 않는다).

## 사용자 발언과 시간

시작 전 마이크 권한을 확인한다. 권한 요청이 8초 안에 끝나지 않으면 안내와 재시도 버튼을 표시하고, 늦게 열린 스트림은 닫는다. 재생 장벽이 끝난 일반 차례에는 지원자가 [발언하기]를 눌러 마이크를 준비하고 서버 발언권 허가 후 녹음한다. 기본 60초이고 `VOICE_USER_TURN_SECONDS`는 1~60초 범위에서 새 채용 건에 복사된다. AI 생성·재생 시간은 발언 한도에 포함하지 않는다. 서버 허가 시각부터 계산하므로 브라우저 녹음 시작까지의 짧은 준비 지연은 한도에 포함된다.

`발언 완료`와 타이머는 동일한 1회 종료 함수를 사용한다. 마지막 MediaRecorder 청크 이후 브라우저에서 PCM16 mono 16kHz WAV로 정규화하고 한 파일을 업로드한다. STT는 파일 EOF까지 확정 결과를 합친다. 받아 적은 글은 기본 8초 동안 편집·확인할 수 있고, 수정하기 시작하면 자동 제출이 멈춰 [발언 제출]을 눌러야 한다. 빈 인식 결과에도 직접 입력해 제출할 수 있다. 제출 글은 기존 WS `message.send`로 보내고 `client_msg_id=utterance_id`로 저장·run 예약을 멱등 처리한다. 서버는 같은 세션의 STT 작업·turn·epoch·generation을 검증하고 제출 글에 기존 마스킹을 적용한다. 원래 인식 글과 수정 여부는 메시지 메타에 보관하며 관리자 전체 기록은 두 글이 다를 때 원문을 표시한다. 토론 그래프와 평가는 제출 글을 사용한다. 부분 전사는 보내지 않는다.

단계 마감·세션 종료는 기존 절대 시각을 유지한다. 발언 한도는 단계/세션 마감으로 잘린다. phase·generation이 바뀌면 미디어를 중단하고 늦은 전사를 새 단계로 저장하지 않는다. 원래 발언 attempt와 오류는 남는다. 녹음·전사 중 AI 자극은 queued로 대기하며 기획안/결정 사항의 확정은 발언 제출 뒤 가능하다. USER_READY의 일반 차례는 채용 건에 고정된 `turn_hold_seconds`(기본 20초) 동안 유지한다. 만료되면 스케줄러가 동료 차례를 넘긴다. 침묵 초대가 이미 전달됐으면 일반 동료 발언으로 이어 간다. 실제로 차례를 넘기기 전까지는 [발언하기]가 가능하다. 실패 후 재시도·다시 녹음 때 유지 시간은 새로 시작한다. 손들기·강제 차례는 생각 시간 + 10초를 쓴다. proposal 단계에는 새 USER_READY나 녹음 허가가 없고, 이전 단계의 대기 중 음성은 재생을 마친다.

## Azure와 비용

TtsService·SttService는 토론 에이전트와 독립 인터페이스다. 기본 어댑터는 Azure F0 일반 Neural TTS와 표준 한국어 STT다. p1 InJoon, p2 SunHi, p3 BongJin voice를 채용 건에 고정한다. 다른 공급자 자동 대체·S0 업그레이드는 없다. F0 조회와 listKeys로 자원·지역·키 소속을 확인하고 검증할 수 없으면 차단한다. 관리 자격증명에는 요금제 변경 권한을 주지 않는다. 외부 운영자가 요금제를 바꾸는 것은 앱 밖의 변경이므로 운영 중 F0 리소스를 변경하지 않는다.

월 운영 한도는 전용 리소스 기준 TTS 400,000 문자·STT 14,400초다. 시작 시 60분 세션은 12,000문자/1,200초, 15분 세션은 3,000문자/300초를 예약하고 종료 세션의 미사용량을 반환한다. 실제 호출 전에 원장을 차감한다. 타임아웃·재시작으로 과금 여부가 불확실해도 차감을 되돌리지 않는다. 한도 초과·원장 장애는 호출 차단이다. TTS는 공용 15회/60초, 세션당 TTS 100회·STT 40회 제한이다. 클라우드 음성 시연은 한 세션만 허용한다. FakeSpeech는 내부 테스트 전용으로 여러 격리 세션을 허용한다.

`VOICE_QUOTA_PERIOD`는 원장 기간 ID다. `auto`(예시 기본값)는 UTC 연-월(`YYYY-MM`)로 달마다 새 원장을 쓰고, 그 밖의 값은 운영자가 정한 ID 그대로이며, 빈 값은 음성을 막는다. 앱 상한(STT 4시간·TTS 40만 자)이 F0 무료량(5시간·50만 자)보다 낮아 Azure 리셋과 며칠 어긋나도 흡수되고, F0는 한도를 넘으면 과금 없이 거부한다. 같은 키를 외부 도구와 공유하면 원장 밖 사용이 생기므로 전용 자원을 사용하고 수동 사용도 대조한다. 무료 사용을 목소리마다 중복 배정하지 않는다.

기존 `SESSION_COST_HARD_USD`는 토론 LLM만 대상으로 유지한다. 음성은 F0만 허용하며 작업마다 단위·수량·시도·순비용 0·청구 상태를 별도 기록한다. 불확실한 호출의 순비용은 null이다. SessionRecord의 `facts.voice_usage`에서 음성 사용량과 불확실 상태를 확인한다. `sessions.cost_usd`는 기존 LLM 합계에 확인된 음성 비용 0을 합한 값이다. 유료 음성·전체 유료 비용 상한 확장은 구현하지 않았으며 유료 SKU는 실행하지 않는다.

## 오류·복구·평가

재생은 실패한 항목부터 캐시 자산으로 재시도한다. 자산이 없는 TTS와 같은 파일 STT는 최대 2시도다. 자동 무한 재시도는 없다. 무음/빈 전사는 자동으로 메시지를 만들지 않으며 지원자가 글을 직접 쓰거나 다시 발언할 수 있다. 마이크 오류는 기능 안내이며 행동 근거로 사용하지 않는다.

현재 구현은 녹음 원본이 서버에 도착하기 전 새로고침/연결 단절로 잃은 파일을 복구하지 못한다. 연결 종료·단계 전환·탭 교체 시 미디어를 중단한다. 업로드 완료 파일·전사·재생 확인은 DB로 복구하고, WS 재연결은 새 epoch를 발급한다. old epoch 명령과 이전 탭 WS 제출은 거부한다. STT 결과가 준비됐지만 ack가 사라지면 같은 ID로 재제출한다. 브라우저가 들은 뒤 ack가 유실되면 항목을 다시 들을 수 있다.

공급자 작업은 호출 전 processing을 커밋한다. TTS processing이 120초 넘게 남으면 오류로 바꾸고 명시적 재시도를 요구한다. 발언권은 발언 마감+100초를 넘기지 않는다. 재생 대기 동안 DB 락이나 메일박스를 붙들지 않는다. 토론 그래프 체크포인터·새 MCP는 추가하지 않는다.

카드 게시 기록은 유지하지만 음성 세션의 `observations.delivered`는 담당 자리의 TTS ended 확인을 기준으로 계산한다. 발언 없는 카드는 기존 관찰을 유지한다. 음성 장애·미청취 메시지·불확실 비용은 facts에 전달하며 음색·억양·발음·말의 속도를 평가하지 않는다. 척도·앵커·평가 모델은 그대로다.

원음은 STT 성공 시 지우고 실패 원음·TTS 자산은 최대 24시간 후 삭제한다. 세션이 끝나면 다음 스케줄러 틱에 오디오 bytes를 비운다. 상태·전사·사용량 기록은 세션 보관 기간에 묶이고 세션 삭제 시 함께 삭제된다. 자산은 세션 JWT 인증·소속 확인 후 no-store로 제공한다.

## 실행·검증

`infra/.env.example`의 Azure 설정을 실제 `.env`에 채우고 새 스키마·채용 건으로 실행한다. 새 DB는 schema.sql을 적용한다. 기존 로컬 DB는 [DB 가이드](../guides/database.md)에 따라 백업한 뒤 음성 테이블 3개의 DDL만 추가할 수 있다. 기존 개발 DB를 초기화하지 않는다. F0 설정이 없으면 시작을 차단한다. 재연결할 기존 음성 세션에도 같은 공급자 설정을 유지해야 한다.

격리 스택의 모드는 프로필이 정한다. `test-text`는 가짜 LLM·음성 끔, `test-voice`는 가짜 LLM·FakeSpeech, `eval-text`는 실제 LLM·음성 끔, `eval-voice`는 실제 LLM·FakeSpeech다. FakeSpeech TTS는 짧은 무음 WAV이며 한국어 음질 검증이 아니다. 내부 `/test/voice-transcript`로 전사 결과만 지정하고 음성 프로필에서는 실제 브라우저의 녹음·업로드·재생 이벤트를 통과한다. 실 Azure·한국어 품질 검증은 별도 live 작업이다. 현재 클라우드 키를 제공하지 않으면 실제 전사·합성 품질을 확인했다고 보고하지 않는다.

## OpenAI 공급자(`VOICE_PROVIDER=openai`)

`VOICE_PROVIDER=openai`이면 Azure 대신 OpenAI 음성을 쓴다(제한 키 프로젝트에 음성 모델 권한이 있어야 함). 어댑터는 `services/api/app/voice/speech.py`의 `OpenAISpeech`이고, 화면·턴 제어·저장 경로는 Azure와 같다(공급자 객체만 바뀜).

- 받아 적기: `/v1/audio/transcriptions`에 완성 WAV(PCM16 mono 16kHz)를 한 번에 보낸다. 모델 `MODEL_STT`(기본 `gpt-4o-mini-transcribe`), `language=ko`. 구문 목록(동료 이름 등)은 `prompt`로 넘긴다. 말하는 동안 받아 적기(`live.py`)도 같은 메서드를 조각마다 부른다.
- 읽기: `/v1/audio/speech`에 `response_format=pcm`(24kHz)으로 받아 길이가 맞는 WAV 머리를 붙인다. 모델 `MODEL_TTS`(기본 `gpt-4o-mini-tts`). 목소리는 자리별 고정(p1 `ash`, p2 `coral`, p3 `sage`)이고 말투 지시는 세 자리 모두 같다.
- 키: 제한 키(`OPENAI_API_KEY`)의 음성 허용 목록(`app/agent/llm/roles.py` `RESTRICTED_SPEECH_MODELS`). 목록 밖 모델이나 빈 키는 `voice_unavailable`로 멈춘다. `verify()`는 외부 호출 없이 설정만 본다. 모델 권한이 없는 프로젝트는 실제 호출에서 403이 나고 그 작업은 `voice_speech_failed`가 된다.
- 비용: F0 무료 등급이 아니라 사용량 과금이다. 채용 건 정책은 `version: openai-v1`, `sku: null`, `paid_budget_usd: null`로 복사되고, 작업 기록은 `billing_status: metered`, `net_cost_usd: null`이다. 사용량 원장은 `openai:<기간>`이며 월 한도·동시 1세션·분당 TTS 15회 제한은 Azure와 같다.
- 정책이 다른 공급자로 만든 채용 건은 시작할 수 없다(`candidate.py`). OpenAI로 바꾼 뒤에는 새 채용 건을 시드한다.

## Gemini 공급자(`VOICE_PROVIDER=gemini`)

`VOICE_PROVIDER=gemini`(또는 `VOICE_TTS_PROVIDER=gemini`)일 때의 공급자다. 어댑터는 `speech.py`의 `GeminiSpeech`이고 키는 기존 규칙(gemini-* → `GEMINI_API_KEY`)을 따른다.

- 받아 적기: `models/{MODEL_STT}:generateContent`에 완성 WAV를 인라인 오디오로 보내고 "들리는 그대로 받아 적어라(다듬기·요약 금지, 말소리가 없으면 빈 문자열)" 지시를 붙인다. 기본 `gemini-3.5-flash-lite`, temperature 0. 전용 음성 인식이 아니라 생성 모델이므로 말을 다듬거나 지어낼 위험이 있다(전사는 평가 근거라 실제 발언으로 확인한다). 구문 목록은 지시에 붙인다.
- 읽기: TTS 모델(기본 `gemini-2.5-flash-preview-tts`)에 `responseModalities: AUDIO`와 자리별 고정 목소리(p1 `Charon`, p2 `Kore`, p3 `Orus`)를 보낸다. 원시 PCM(`audio/L16;rate=24000`)이면 WAV 머리를 붙이고, WAV로 오면 그대로 쓴다. 말투 지시는 세 자리 모두 같다. 10/25 시험에서 한 문장에 약 5초가 걸렸다.
- 비용·정책: 사용량 과금. 정책 `version: gemini-v1`, 원장 `gemini:<기간>`, 과금 표시는 OpenAI와 같다(`metered`).
- 데이터: Gemini API 무료 티어는 입력을 Google이 제품 개선에 쓸 수 있다. 실제 지원자 음성에 쓰기 전에 키 프로젝트의 결제 티어를 확인한다. 동의 화면은 처리 업체를 "Google Gemini"로 적는다(`NEXT_PUBLIC_VOICE_PROVIDER`).

## 받아 적기·읽기 분리(`VOICE_STT_PROVIDER`·`VOICE_TTS_PROVIDER`)

두 값을 따로 주면 `SplitSpeech`가 받아 적기는 STT 공급자, 읽기는 TTS 공급자에 맡긴다(비우면 `VOICE_PROVIDER` 하나). 채용 건 정책의 `provider`는 `"<stt>+<tts>"`(예: `whisper+gemini`), 목소리는 읽기 공급자 것을 복사하고, 사용량 원장은 `<stt>+<tts>:<기간>`이다. 과금 표시는 그 작업을 맡은 쪽이 과금 공급자일 때만 `metered`다.

`dev-real`은 받아 적기 `whisper`(로컬) + 읽기 `gemini`다.

- 로컬 받아 적기(`WhisperSpeech`): faster-whisper(CPU int8)를 API 프로세스 안에서 돌린다. 모델 `WHISPER_MODEL`(기본 `large-v3-turbo`), 스레드 `WHISPER_THREADS`(기본 4), 빔 `WHISPER_BEAM`(기본 1), 동시 처리 `WHISPER_CONCURRENCY`(기본 1). 완성 WAV의 PCM을 배열로 넘기고, 구문 목록은 `initial_prompt`로 넘긴다. 모델은 첫 사용(세션 시작 확인 `verify`) 때 `/models/whisper`(compose `hfcache` 볼륨)에 내려받아 프로세스에 하나만 둔다. 지원자 소리는 서버 밖으로 나가지 않고 과금이 없다.
- 읽기는 Gemini TTS로, 개인 Gemini 키에는 AI 동료가 만든 문장만 간다(지원자 음성·발언은 보내지 않는다).
- 동의 화면은 "이 서비스 서버(외부 전송 없음)에서 받아 적고, AI 동료 음성은 Google Gemini"로 적는다.

## 가운데 칸 배치와 상태 표시(2026-10-25)

- 가운데 칸은 위에서부터 4명 프로필(한 줄), 최근 발언(남는 높이 전부, 집중 칸), 조작부다. 최근 발언은 들은 동료 발언과 지원자 발언을 오래된 것부터 최대 30개 쌓고, 가장 새 발언을 아래에 크게 둔다. 재생 중인 발언은 말한 데까지 보이고 끝에 커서가 깜빡인다. 위로 갈수록 작고 흐려지며 칸 위·아래 가장자리는 서서히 사라진다. 지원자가 위로 스크롤한 동안 새 발언이 오면 [새 발언 n개]가 뜬다(`components/debate/voice/recent-talk.tsx`). 조작부 안의 접는 [최근 발언] 목록은 이 칸으로 옮겼다.
- 프로필 카드는 상태를 심볼과 글자로 함께 보인다: 발언 중·준비 중(동료), 녹음 중·손 듦·내 차례(지원자)(`voice/status-symbols.tsx`). 말하는 카드는 살짝 떠오르며 테두리 빛이 퍼진다. 움직임 줄이기를 켜면 멈춘다.
- 왼쪽 열(메모·진행 상황)은 폭 272px·진행 상황 높이 210px로 고정하고 끌 수 없다. 나머지는 가운데 칸이 먼저, 그다음 결정 사항·기획안, 자료·AI 어시스턴트 순으로 공간을 나눈다. 오른쪽 칸을 모두 끄면 오른쪽 열이 사라지고 가운데가 넓어진다. 숨어 있던 칸이 생기면 떠오르며 테두리가 한 번 빛난다.
- 손들기는 동료가 말하는(준비하는) 동안에만 보인다. 버튼 아래에 "동료가 말하는 중에 끼어들고 싶을 때 눌러요"를 적는다.

## TTS 실패 시 글로 넘기기·가벼운 TTS(2026-10-25)

- Gemini 기본 TTS는 `gemini-3.8-flash-lite-tts`다. 이 모델은 본문 앞의 말투 지시문까지 소리 내 읽고 시스템 지시도 받지 않아, 말투 지시는 지시를 알아듣는 2.5 계열(`GEMINI_STYLE_TTS_MODELS`)에만 붙이고 3.8 계열에는 본문만 보낸다. 세 자리의 차이는 목소리뿐이다.
- 동료 발언의 음성을 만들지 못하면(합성 실패·무료 티어 하루 한도 초과·타임아웃 등, status error) 화면은 그 발언을 자막처럼 글로 보여 주고 읽을 시간(초당 약 8자, 2.5~12초) 뒤 `/playback` `text`를 보낸다. 서버는 heard로 기록하고 다음 발언이나 내 차례로 넘어간다. 스피커 재생 실패(`voice_playback_failed`)는 지금처럼 [다시 재생]을 보인다. 이 처리는 텍스트 기록·평가 근거를 바꾸지 않는다(메시지는 원래대로 저장된다).
- 무료 티어 Gemini 키는 모델당 하루 요청 수가 작다(10/25 `gemini-2.5-flash-preview-tts` 하루 10회). 한도가 차면 위 처리로 글로 이어지고, 실제 시연에는 결제(유료 티어)를 켠다.
