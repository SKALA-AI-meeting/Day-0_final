# 화면 흐름

지원자는 AI 동료 3명과 음성으로 토론하고 결정 사항·자료·어시스턴트·기획안을 우측 탭에서 사용한다. 참여자는 동등하며 성향 유형·평가 정보는 토론 화면에 표시하지 않는다.

## 지원자

초대 링크 → 동의(음성 전사·보관 안내, 표시 이름) → 대기 → 마이크 권한 확인 → 시작 → 음성 회의 → 기획안 제출 → 나가기 → 디브리핑·설문 순서다. 시작 전 마이크를 확인하지 못하면 세션 시계를 시작하지 않는다. 실제 Azure F0 확인·무료량 예약도 시작 조건이다.

## 음성 회의

중앙에는 네 참여자의 아바타·이름·발언 상태가 있다. 공용 채팅 입력창·말풍선·입력 중 표시는 없다. AI 음성이 순서대로 재생되고 모든 실행과 재생이 끝나야 내 차례가 된다. 마이크는 이때 활성화된다. 내 발언 남은 시간·음량·발언 완료 버튼을 표시하고 최대 60초 뒤 자동 제출한다. 완료 버튼도 같은 종료 함수를 사용한다.

최종 녹음만 전사하고 전사 중에는 재녹음·결정 사항 확정을 막는다. 무음/빈 전사와 장치 오류는 기능 안내·명시적 재시도를 제공하며 허구의 발언을 만들지 않는다. 재생 실패는 같은 음성 재시도 버튼을 제공한다. 단계 마감·세션 마감은 계속 흐르고 마감 뒤 발언을 다음 단계 의견으로 옮기지 않는다.

## UX 결정 (G-U)

상단에는 단계 진행과 남은 시간을, 우측에는 결정 사항·자료·AI 어시스턴트·기획안 탭을 둔다. 지원자에게는 정할 항목·결정 사항·이걸로 정하기라는 표현을 사용한다. 후보안의 숨은 지지 현황·성향 유형은 노출하지 않는다.

키워드는 후보 4개에서 선택해 확인한다. 문제 상황·해결책은 현재 항목의 입력과 확인을 사용한다. 합의 여부와 시간 초과 선택은 기존 서버 규칙이 판단하며 지원자가 직접 정하는 확인 흐름도 유지한다. 음성 발언 제출을 마친 뒤 이걸로 정하기를 사용할 수 있다.

키워드 확정 후 해당 자료만 열린다. 어시스턴트는 열린 자료를 사용하는 지원자 전용 요청·응답 목록이며 공용 음성 큐에 참여하지 않는다. 기획안은 6개 필드·디바운스 저장·빈 필드 경고·제출 확인을 유지한다. proposal 단계만 기획안 제출이 가능하다.

## 종료·재연결

연결 단절·다른 탭 교체·단계 전환·종료 시 미디어를 중단한다. 재연결은 일반 state와 voice state를 읽어 복구하고 최종 전사 제출은 같은 ID를 재사용한다. 서버 도착 전 녹음 원본을 잃으면 복원할 수 없다는 안내를 제공한다. 세션 종료 후에는 마이크·재생을 잠그고 나가기로 디브리핑에 이동한다.

## 담당자

기존 가입·로그인 → 채용 건 생성·초대 → 지원자 목록 → 리포트·전체 기록 → 차원별 검토·메모 → 검토 완료 흐름을 유지한다. 내부 메시지와 행동 근거는 보존한다. 자세한 구성은 [web 서비스](../services/web.md)와 [평가 규칙](rubric.md), 음성 상태·오류는 [음성 구현](../architecture/voice.md), 인터페이스는 [음성 계약](../contracts/voice.md)을 따른다.

## 유지되는 보조 화면 상세

### 우측 패널: 탭

탭: [결정 사항] [자료] [AI 어시스턴트] [기획안]. 분절 컨트롤(segmented control) 모양. 탭을 바꿔도 각 탭의 스크롤·입력 중 내용은 유지한다. 기본 탭은 토론 단계에서 결정 사항, proposal 단계 시작 시 기획안으로 자동 전환한다.

**결정 사항 (ConsensusPanel)**
- 단계마다 정한 결과만 짧게 쌓인다: "키워드 · 물 · 합의", "문제 상황 · 가뭄으로 생활용수 제한 · 시간 초과". 오피스 시각은 넣지 않는다(R7). `resolution`은 아이콘 + 글자("합의"/"지원자 결정"/"시간 초과", 규칙은 [contracts/README.md](../contracts/README.md) "칸 결과 표시"), 정한 사람(`filled_by`)의 이름을 작게. 얇은 구분선으로 나눈 목록이며 줄마다 카드를 따로 두지 않는다.
- **후보안·지지 현황은 보이지 않는다**(D14). 토론은 음성으로 진행한다. `/state`에도 내려오지 않는다.
- 현재 단계의 정할 항목(SlotInput)만 입력과 [이걸로 정하기]가 있다. 칸 상태는 `empty | confirmed` 두 개뿐이고 입력 중인 값은 서버에 저장하지 않는다(`PUT slots`·`slot.filled` 없음, R5-5). [이걸로 정하기]는 확인 창(아래 "UX 결정" 2) 뒤 `POST .../confirm{value}`. 빈 값이면 버튼 비활성.
- keyword 항목은 후보 4개 분절 버튼 중 하나를 골라 옵션 키로 정한다. 방어용으로 422 `invalid_keyword`가 오면 항목 아래 한 줄로 보인다. problem·solution은 짧은 글 입력이다(서버는 LLM 없이 안과 연결).
- AI 동료가 정하거나 시간 초과로 정해지면 WS `slot.confirmed`로 항목이 잠기고 결과 줄이 쌓인다. 화면에만 있던 입력 값은 버린다. AI 합의 채우기는 칸 확정과 채운 자리의 공지("그럼 X로 정리할게요.")가 서버에서 함께 저장되므로 공지 `message.new`가 먼저 오고 이어서 `slot.confirmed` → `phase.changed` → `timer`가 온다. 공지 없이 칸만 잠기는 경우는 없다.
- 시간 초과 안내 문구(R7, api 고정 문장): "시간이 다 돼서 대화에서 가장 많이 모인 의견인 X로 할게요." 우선순위 자리(서지안)의 메시지로 온다.
- 오류: 409 `phase_not_open`·`slot_confirmed`면 `/state`를 다시 읽고 "이미 정해진 항목이에요" 한 줄.

**자료 (MaterialList + MarkdownViewer)**
- 키워드 확정 전: 잠금 아이콘과 한 줄 "키워드가 정해지면 자료가 열립니다." 목록 없음.
- WS `materials.opened{keyword, materials}`로 열린다. 시스템 안내 "「물」 자료가 열렸어요" 한 줄과 탭 배지.
- 목록은 제목만, 누르면 Markdown 뷰어(읽기 전용, 제목·목록·표·강조, 읽기 좋은 본문 폭). 열람은 `GET .../materials/{material_id}`가 기록한다. 423 `not_released`면 목록을 다시 읽는다.
- 확정 키워드에 자료가 없으면(정본상 막혀 있지만 방어) "이 키워드에는 준비된 자료가 없어요".

**AI 어시스턴트 (AssistantPanel)**
- 지원자 전용. 요청·응답 목록(말풍선 아님, 구분선으로 나누고 요청은 인용처럼 작게·응답은 본문), 응답은 제한 마크다운(굵게·기울임·목록·문단·코드만, 링크는 글자만, 이미지·제목·HTML은 글자로 강등), 입력 안내 "열린 자료에 대해 물어보세요", 인용 자료 제목 칩(어시스턴트가 도구로 찾은 자료, R5-13), 응답 대기 표시, 응답마다 "복사"(기획안에 직접 쓰지 않으므로 복사가 기본 동선). 반짝이·로봇 아이콘을 쓰지 않는다.
- 열린 자료만 검색한다는 한 줄 안내(기능 설명). 429 `assistant_limit`이면 "이 세션의 요청 한도를 다 썼어요".
- 토론방과 분리된 대화다. AI 동료는 이 대화를 보지 않는다.

**기획안 (ProposalEditor)**
- 템플릿 6칸: 키워드 · 문제 상황 · 해결책 · 근거 · 기대효과 · 아이디어 기여(필드 id `keyword`·`problem`·`solution`·`rationale`·`expected_effect`·`idea_credit`). 칸마다 제목과 textarea, 예시 문장 없음(결정 사항의 문제 상황·해결책 입력에는 형식 안내만: "누가 어떤 상황에서 무엇이 어려운지 한두 문장으로 적어요", "누가 무엇을 어떻게 하는지 한두 문장으로 적어요"). 문서처럼 넓은 여백.
- `idea_credit` 칸에는 무엇을 적는 칸인지만 중립적으로 한 줄 안내한다(R7): "이 기획에 반영된 의견과 그 의견을 낸 사람". 적으라고 권하거나 누가 냈는지 알려 주는 문구는 쓰지 않는다.
- 진행 중 언제든 쓸 수 있고(`PUT /sessions/{id}/proposal{sections, revision}`, 1초 디바운스, 마지막 저장 시각 표시), 제출은 proposal 단계에서만. 409 `conflict`(다른 탭)면 최신을 다시 읽고 "다른 창에서 고친 내용으로 바꿨어요" 토스트.
- proposal 단계 시작 때 앞 3칸이 비어 있으면 서버가 확정 칸 값으로 채운다(`/state` 재조회로 반영). 지원자가 고칠 수 있다.
- [제출]: 저장 대기분을 먼저 PUT → 빈 칸이 있으면 빈칸 경고 창(빈 칸 이름 목록, "비워 둔 칸이 있어요. 그대로 제출할까요?", [그대로 제출]·[돌아가서 쓰기]) → 확인 창("제출하면 수정할 수 없어요", [제출]·[취소]) → `POST .../proposal/submit`(경고 창을 거쳤으면 `blank_warning_shown: true`). 토론 단계에서는 [제출] 비활성 + "기획안 작성 단계에서 제출할 수 있어요".
- 화면은 우측 탭 안 6칸 세로 폼이다.

**새 소식 표시**: 토론방은 늘 보이므로 메시지 알림이 따로 없다. 우측 탭은 자료 열림·칸 확정에만 배지를 단다.

### 단계 전환

- WS 순서: `slot.confirmed` → `phase.changed{phase, previous_phase, reason}` → `timer` → (keyword였으면) `materials.opened` → 시스템 안내 `message.new`. AI 합의 채우기면 그 앞에 채운 자리의 공지 `message.new`가 온다.
- 진행바가 다음 칸으로 넘어가고, 결정 사항에 결과 줄이 쌓이고, 새 단계의 정할 항목이 열린다. 시간 초과(`reason: timeout`)면 결과 줄과 진행바 아이콘이 "시간 초과"로 보인다.
- 연출은 진행바 칸 이동 + 결과 줄 짧은 강조 + 음성 회의의 상태 안내뿐이다.

### 종료 → 디브리핑

- 제출 성공 또는 WS `session.ended{reason}`을 받으면(submitted·timeout이면 세션은 이미 completed) 입력창·칸·기획안·어시스턴트를 모두 잠그고 상단에 **[나가기]** 버튼을 띄운다. 누르면 디브리핑으로 화면만 이동한다(API 호출 없음).
- 자동 제출(`reason: timeout`, `proposals.auto_submitted`): 같은 흐름이고 디브리핑 머리에 "시간이 끝나 지금 상태로 제출됐어요" 한 줄.
- `failed`: "세션이 중단됐어요. 담당자가 새 링크를 보낼 수 있습니다." `cancelled`: 취소 안내.
- [나가기]를 누르지 않고 이탈하면 재접속 시 `GET /s/{token}`이 completed라 바로 디브리핑으로 간다.
- 재연결: WS가 끊기면 3초 후 재연결하고 `/sessions/{id}/state`로 전체 갱신(메시지·칸·기획안·자료·어시스턴트·typing·active_runs). 연결 중에도 프레임 봉투의 세션 단위 `seq`가 비면(앞 번호 누락) 같은 방식으로 `/state`를 다시 읽는다(R5-10). close 4401이면 `/s/{token}/resume`으로 JWT 재발급, 4403·4000은 재연결하지 않는다(4000은 "다른 창에서 열렸어요").

### 디브리핑

`GET /sessions/{id}/debrief`(세션 JWT 또는 debrief_token). 큰 제목과 넓은 여백의 한 열 문서.
- "수고하셨습니다" 다음 첫 문장(R1, 고정): "같은 채용 건의 모든 지원자가 같은 장면을 겪었고, 정답 없이 반응을 봅니다." 바로 아래 "평가 결과는 보여 드리지 않습니다."(`scoring_notice` 첫 문장)와 이의 제기 경로(문의 창구와 절차 한 줄). 설문 제출 확인은 성공 표시(success-soft 면·체크 아이콘). 내 발언 돌아보기·제출한 기획안은 접힘 구간.
- 실제 발동한 카드마다 고정 설명 문장(`cards[].description`, 원천은 `observations`)과 관련 평가 요소 이름·"이렇게 봅니다" 한 줄. 척도 세부·차원 앵커는 보이지 않는다.
- 내 발언 돌아보기(R7): 토론 단계(키워드·문제 상황·해결책)마다 가장 긴 본인 발언 1개, 최대 3개를 읽기 전용으로 보인다(`my_messages`, 선택은 api). 평가·설명 없이 원문과 메시지 시각만.
- AI 동료 소개: 자리별 이름·프로필 이미지와 성향 설명(`seats[].persona_description`). 이때 처음으로 유형이 드러난다.
- 평가 결과를 보여 주지 않는 이유(`scoring_notice`), 기업이 보는 것(대화·어시스턴트 요청 원문, 제출 기획안), 끊긴 구간이 있었다면 담당자에게 알리라는 안내, 기록 보관 90일, 이의 제기·문의 창구.
- 제출한 기획안 읽기 전용 열람과 복사(종료 후 7일, `view_until`).
- 종료 설문 2문항(자연스러웠나 `natural` / 공정했나 `fair`, 1~5)과 자유 의견 한 칸(R7). 모두 건너뛰기 가능, 한 번만.
- 세션 실패면 카드·성향·기획안 없이 중단·재응시 안내만.


## 관리자: 채용 건 생성

- 입력은 이름과 세션 길이뿐이다. **요소 선택 UI는 없다**(R2): 모든 채용 건이 같은 5요소·같은 척도를 쓴다.
- 세션 길이: 60분(기본) / 15분(데모, R3), 분절 컨트롤. 미션은 MVP 고정 1개라 선택 UI 없음.
- 보는 요소 안내(읽기 전용, `GET /admin/catalog`의 elements): 설득/논리력, 경청/존중, 배려/포용, 수용/유연성, 정직/공정. 항목마다 이름·한 줄 뜻·"이렇게 봅니다" 2~3줄, 얇은 구분선 목록. 체크·스위치 없음. **페르소나 유형·카드 장면·차원 앵커는 보이지 않는다.**
- 안내 줄: "모든 채용 건이 같은 요소와 같은 척도로 기록됩니다." 아래 "샘플 리포트 보기".
- 생성 응답의 `seats`(이름)와 `keywords`(후보 4개)는 확인용으로 이름·키워드만 보인다. 유형은 리포트에서 본다.

## 관리자: 지원자 목록·초대

- 초대 폼: 별칭(설명 "지원자에게 이 이름으로 안내되고 세션과 리포트에 남습니다"), 이메일. 같은 채용 건 중복 별칭은 제출 전에 막는다. 응답의 `invite_url`·`notice_text` 복사 버튼(발송하지 않음).
- 링크 재발급(`POST /admin/sessions/{id}/reissue`, R5-20)은 시작 전·만료 행에서: 같은 세션·같은 별칭으로 토큰과 만료만 바꾸고 새 `invite_url`을 복사한다. 재응시 초대(previous_session_id, 새 세션)는 세션 실패·취소 행에서만. 두 버튼의 설명을 한 줄씩 구분해 둔다.
- 상태 묶음(필터 겸용, `display_group`): 대기 / 진행(현재 단계 `phase`, 시작·종료 예정 시각) / 검토 필요 / 완료 / 문제. 목록은 표(얇은 행 구분선)이며 행마다 카드를 두지 않는다.
- 행마다 마지막 활동 시각·메시지 수·삭제 예정일(`purge_at` = 종료 시각 `ended_at` + 90일, 완료·실패·취소 모두). 실패 행은 담당자 행동 안내(`next_action`).
- 평가는 **요소별 수준 칩**("설득 3"처럼 요소 짧은 이름 + 최종 수준 1~5, 기록 없음이면 "—")과 **확신도 low 차원 수**("근거 약함 2"), 출처(자동/담당자 조정). 합계·평균 없음, **수준 정렬·순위 없음**(표 정렬 키로 쓰지 않는다).

## 관리자: 리포트 화면

D13-2 톤: 흰 바탕, 한 열 문서처럼 읽히는 구조, 큰 제목과 분명한 위계, 얇은 구분선. 색은 수준·확신도 칩과 참여자 표시에만 쓰고 카드만 반복되는 대시보드로 만들지 않는다. 채용 관계자가 바로 읽을 문장으로 쓰고 코드 id는 화면에 보이지 않는다(차원은 [product/rubric.md](rubric.md)의 한국어 이름으로). **총점·합계는 어디에도 없다.**

**머리**
- 단계 배지(검토 대기 / 확정 중 / 검토 완료), 검토자 이름, 삭제 예정일, "인쇄".
- 고정 문구: "이 리포트는 담당자가 평가할 때 보는 참고 자료입니다. 수준은 세션 뒤 AI 평가 에이전트가 공개된 척도로 근거를 들어 판단한 값이며, 담당자가 원문을 보고 차원 단위로 조정해 최종 평가합니다. 합격·불합격·순위는 판정하지 않습니다."
- 설계된 장면 표시(R1, 담당자용 고정 문구): "동료의 반대·압박·머뭇거림 같은 장면은 같은 채용 건의 모든 지원자에게 같게 설계된 장면입니다. 지원자 안이 채택되지 않은 것은 설계의 결과일 수 있습니다." 타임라인의 카드 표식과 요소 섹션의 "관련 카드 장면"에도 "설계된 장면" 칩을 붙인다.
- 참여자: 지원자 별칭(표시 이름이 다르면 함께), 자리별 이름·프로필 이미지와 유형(`seats[].persona_type`의 한국어 이름).
- **요약표**: 요소마다 한 행. 요소 이름, **"수준 N (1~5)"**(`elements[].level`, null이면 기록 없음 표시 문장), 서술 1~2줄(`summary`), 기록 없음 차원 수(`no_record_count`/`dimension_count`), 확신도 low 차원 수, 담당자 조정 값(`adjusted_level`)이 있으면 자동 값 옆에 "담당자 조정됨"과 함께. 합계 행 없음. 행을 누르면 해당 요소 섹션으로.

**① 토론 흐름 (타임라인)**
- 가로 단계 띠: 단계별 칸 결과(`slots[]`: 값, 합의/시간 초과, 채운 사람, 확정 시각), 확정 시점 지지 현황(`support`: 안별 지지자 이름), 확정 안의 최초 제안자(`first_proposer`).
- 카드 발동 표시(`cards[]`: 단계, 발동 시각, 관찰 창, 장면 한 줄(`scene`, 카드의 고정 문장), "설계된 장면" 칩, 미발생이면 "이벤트 미발생", 발동했지만 담당 동료 일부만 전달했으면(`delivered=false`) "일부 동료만 전달됨"). 누르면 그 요소 섹션으로.
- 접속 끊김 구간(`connection_gaps`)을 회색 띠로.

**② 요소 섹션**
- 요소마다 소제목·"수준 N (1~5)"·서술. 차원 3~4개(`dimensions[]` 중 그 요소)가 접힌 상태로, 소제목 줄에 차원별 수준 칩과 확신도 표시만 미리 보인다.
- **차원(DimensionRow)**을 펼치면: 차원 이름과 정의 한 줄, **수준 칩**("수준 4", 기록 없음이면 사유 문장), **확신도**(높음/보통/낮음, 아이콘 + 글자), 판단 이유(`rationale`), 관련 카드 장면, 담당자 참고 문구(해당 수준의 앵커 행), 근거 목록. 확신도 `low`면 차원 옆에 **"근거 약함, 원문 확인 권장"**을 warning 톤 글자로 붙인다(색만으로 표시하지 않음).
- **근거(EvidenceItem)**: 참조 종류별로 보인다. `msg:`는 오피스 시각·단계·원문 인용(참여자별 색·이름)·자발/초대 후(`origin`). `slot:`은 단계·값·합의/시간 초과·채운 사람·지지 현황. `proposal:`은 기획안 필드 이름과 발췌. `contribution:`과 AI 동료 메시지는 "맥락" 칩을 달고 흐리게(근거 개수에 들지 않음). **근거를 누르면 그 자리에서 원문과 앞뒤 맥락(앞 5·뒤 3 메시지)이 펼쳐지고** 근거 메시지는 accent-soft로 강조한다. 근거마다 "기록에서 보기"(`record_ref` → `/admin/sessions/{id}/record#<id>` 하이라이트). 보조 장면 근거는 `rationale`에 표시된 대로 "보조 장면" 칩.
- **담당자 조정(draft에서만, 차원 단위)**: 차원마다 [조정] → 수준 선택(1~5 분절 컨트롤) 또는 "기록 없음"(사유 선택)과 **메모(필수)**. 메모가 비면 저장 비활성. 조정하면 자동 값(회색)과 담당자 값·메모가 나란히 보이고, 요소 수준은 조정된 차원으로 다시 계산해 "담당자 조정됨"을 붙인다. 자동 서술은 그대로 둔다.
- 기록 없음 사유는 문장으로 매핑한다([product/rubric.md](rubric.md) 5장). 지원자 안이 채택돼 수용 장면이 없었으면 수용 차원은 `not_applicable`이다(R1).

| 사유 | 화면 문장 |
|---|---|
| no_activity | 지원자 활동 없음 |
| evaluate_failed | 판단 보류 · 근거 부족 — 원문 기록 확인 권장 |
| not_applicable | 해당 없음 |
| event_not_fired | 이벤트 미발생 |
| auto_submitted_blank | 자동 제출로 기여 칸 미작성 |

- 정직/공정 섹션: 기여 대조표(`contribution_check`: 안별 실제 최초 제안자 / 기획안에 적힌 기여자)와 제출 기획안의 `idea_credit` 원문을 나란히.

**③ 사실 지표**: `facts`를 표로. 발언 수(단계별), 자발/초대 후 수와 비율, 응답 간격 중앙값, 의도별 수 등([product/rubric.md](rubric.md) 6장 지표의 한국어 표기). "수준 판단에 쓰인 참고 기록이며 이것만으로 수준을 정하지 않습니다" 한 줄.

**④ 제출 기획안**: 6칸 읽기 전용, 제출 시각, 자동 제출이면 "시간 종료로 자동 제출".

**⑤ AI 활용**: "판단 기준 없음, 면접 확인용". 요청·응답·인용 자료를 시간순으로만. 분류·비율 없음. 각 호출에 "기록에서 보기".

**검토 완료**
- 하단 검토자 이름(필수)과 [검토 완료]. 확인 창 "검토 완료 후 수준은 바꿀 수 없습니다. 메모는 계속 추가할 수 있습니다." → `POST /review{reviewer_name, adjustments: [{dimension_id, level, no_record_reason?, memo}]}`(R5-16) → "확정 중…" → 폴링으로 final이면 검토 시각·검토자. 검증 오류(422, 이름·메모 비어 있음 등)는 해당 입력 아래 한 줄, 409 `already_reviewed`면 최신 리포트를 다시 읽는다.
- 확정 실패 시 "조정은 저장되어 있습니다. 확정만 다시 시도합니다."와 재시도.
- final에서는 값 입력이 잠기고 리포트 메모 추가만(`POST .../report/notes`).

**인쇄**: 인쇄 CSS로 브라우저 PDF(항상 라이트). 접힌 차원 전부 펼침(근거 앞뒤 맥락은 근거 메시지만), 토글·버튼·링크 숨김, 머리 문구·검토자·검토 시각 포함.

## 관리자: 전체 기록 화면

- `GET /admin/sessions/{id}/record`의 한 타임라인: 종류 `message`·`slot`·`phase`·`assistant_call`·`material_view`·`proposal_submit`·`connection_gap`. 줄마다 오피스 시각·종류 칩·주체(이름·프로필 이미지 또는 이니셜)·요약. 메시지는 토론방과 같은 참여자 색·이름.
- 필터: 종류, 주체(지원자·AI 동료별·시스템), 단계.
- 리포트에서 들어오면 `#<record_ref id>` 줄로 스크롤하고 accent-soft 하이라이트, 상단 "리포트로 돌아가기". 읽기 전용, 인쇄 CSS.
