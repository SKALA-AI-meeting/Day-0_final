# 사용자 흐름과 화면 규칙

지원자(입장 → 동의 → 대기 → 토론 → 기획안 → 디브리핑)와 관리자(채용 건 → 초대 → 리포트 검토)의 흐름과 화면 규칙이다. 토큰·컴포넌트는 [architecture/design-system.md](../architecture/design-system.md), 구현 구조와 mock은 [services/web.md](../services/web.md), API·WS 필드는 [contracts/api.md](../contracts/api.md)·[contracts/ws.md](../contracts/ws.md).

## 관찰 목적

핵심은 **채팅 과정에서 지원자의 인성이 잘 분석되는 것**이고 UI는 거기에 맞춘다. 화면은 평가를 드러내지 않고, 장면이 자연스럽게 일어나고 행동이 기록되게만 한다.

| 요소 | 장면 | 화면이 해야 하는 일 | 기록 원천 |
|---|---|---|---|
| 설득/논리력 | 내 안과 다른 안이 경쟁 | 누가 무엇을 주장하는지 한눈에 보이는 채팅, 자료 탭(근거 인용) | 지원자 메시지, 자료 열람 |
| 경청/존중 | 고집형 동료가 강하게 밀어붙임 | 화자 구분이 분명한 말풍선(이름·아바타·사람별 틴트) | 지원자 메시지 |
| 배려/포용 | 조용한 동료가 머뭇거림 | 짧은 머뭇거림 메시지도 묻히지 않는 말풍선, 이름으로 부르기 쉬운 표시 | 지원자 메시지 |
| 수용/유연성 | 내 안이 채택되지 않음(지원자 안이 채택될 수도 있다, R1) | 결정 사항에 결과만 쌓이고 다음 단계로 넘어감(결과는 분명, 지지 현황은 숨김) | 칸 확정, 이후 메시지 |
| 정직/공정 | 최종 기획안 제출 | 기획안의 "아이디어 기여" 칸, 토론 기록을 다시 읽을 수 있는 채팅 스크롤 | 제출 기획안 |
| AI 활용(평가하지 않음, 리포트에 시간순 사실만) | 언제든 | 지원자 전용 어시스턴트 탭(열린 자료만) | 어시스턴트 호출 |

- 화면 안내는 기능 설명만 한다. 평가 대상 행동을 유도하는 문구, 빈 상태 예시·추천 문구를 쓰지 않는다. 후보안·지지 현황을 보이지 않아 토론은 채팅으로만 일어난다(D14).
- **지원자 화면 용어**(R7): 이 문서의 내부 용어를 지원자 화면에서는 지원자 말로 쓴다. 칸 → "정할 항목", 합의 패널 → "결정 사항", 확정 → "이걸로 정하기"(버튼)·"정했어요"(안내). 관리자 화면과 문서·코드 이름은 내부 용어 그대로다.
- **시간 표시 한 줄 원칙**(R7): 지원자 화면은 실제 남은 시간을 중심으로 보이고, 남은 시간과 오피스 시각을 한 줄에 같이 쓰지 않는다. 오피스 시각은 메시지 타임스탬프에만 쓴다.
- 참여자는 AI 동료 3명 + 지원자(D13-3). 지원자는 페르소나가 아니며 입장 때 정한 표시 이름(`display_name`, 기본값 초대 이름)으로 보이고 이니셜 아바타를 쓴다. AI 동료는 자리별 `display_name`과 고정 프로필 이미지(`avatar_url`)로 보인다(아래 "프로필 이미지").
- 지원자 화면에는 자리 id와 표시 이름만 쓴다. **페르소나 유형(고집형 등)은 지원자 화면 어디에도 나오지 않는다.** 유형은 관리자 리포트와 디브리핑에서만 보인다.
- 토론방은 "평가 중"이 드러나지 않게 평범한 메신저 모습을 유지한다.

## 레이아웃

가운데 토론방, 우측 패널(탭), 상단 바(D13). 채팅이 주인공이고 우측 패널은 보조다.

```
┌ 상단 바 (얇은 반투명) ────────────────────────────────────────────────────────┐
│ Day Zero   키워드 ✓ ─ 문제 상황 ● ─ 해결책 ─ 기획안 작성         이 단계 12:40 남음  ? │
├ 토론방 ──────────────────────────────────────┬ 우측 패널 ───────────────────────┤
│ 새 프로젝트 팀  [강][윤][서](나)                 │ [결정 사항][자료][AI 어시스턴트][기획안] │
│              문제 상황을 정할 차례예요 · 18분     │                                │
│ 강한결                                  09:12  │ 키워드 · 물 · 합의               │
│ [강] ╭ 가뭄이 제일 시급하죠. 통계도 있고요 ╮     │ ─────────────────────────────  │
│ 윤하람                                         │ 문제 상황                        │
│ [윤] ╭ 음… 저는… ╮                              │ ┌──────────────────────────┐  │
│                    ╭ 침수 쪽이 체감이 커요 ╮ 나  │ │                          │  │
│ [서] ··· 서지안님이 입력 중                      │ └──────────────────────────┘  │
│ ┌ 메시지 입력 ───────────────────────── (↑) ┐   │                 [이걸로 정하기] │
└───────────────────────────────────────────────┴────────────────────────────────┘
```

- 그림의 [강]은 AI 동료 프로필 이미지, (나)는 지원자 이니셜 아바타. 자리는 `p1` 강한결·`p2` 윤하람·`p3` 서지안으로 고정이다(R2).
- 비율 초안: 토론방 60~65%, 우측 패널 35~40%. 최소 폭 1280px(PC 권장). 좁으면 우측 패널을 시트로 접는다(polish).
- 화면에 두는 것: 토론방 하나(DM 없음)와 입력 중 표시, 상단 단계 진행바·단계 남은 시간, 메시지 타임스탬프의 오피스 시각, 우측 탭(결정 사항·자료·AI 어시스턴트·기획안), 시스템 안내(지금 할 일·남은 시간·정한 결과·끊김), 종료 → [나가기] → 디브리핑.
- 두지 않는 것: 레일과 채널 목록, DM·개인 알림, 지지 현황 표시, 리액션·스레드·검색, 파일 업로드, 토큰 스트리밍.
- 세부 구조(혼자 확정·오클릭 처리, 단계 전환 연출, 기획안 작성 화면, 리포트 화면)는 아래 "UX 결정"을 따른다.

## 지원자: 입장·동의·대기

호칭은 "지원자"이고 대화 속에서는 "OO님"이다. 다른 호칭은 쓰지 않는다.

**입장 화면**: `GET /s/{token}`의 `entry_notice`를 그대로 보인다(60분 연속 진행·중간 휴식 없음·PC 권장·새 프로젝트 팀에서 AI 동료 3명과 채팅으로 키워드 → 문제 상황 → 해결책을 정하고 기획안을 혼자 써서 제출·끊겨도 시간은 흐름·외부 도구는 막지 않되 안의 AI 어시스턴트만 기록됨·문의 창구). 응답의 `session_id`와 초대 이름(표시 이름 기본값)을 다음 화면에 넘긴다(R5-19). 만료·취소는 410 안내, completed 이후는 디브리핑 링크(`session_id`로 `/sessions/{id}/debrief`). 큰 제목 하나와 "{세션 분}분 · AI 동료 3명과 채팅 토론" 부제, 문장별 목록 본문, 버튼 하나의 단순한 화면.

**동의 화면**
- 형식 안내(R1, 고정 문구): "토론 결과가 내 제안과 다를 수 있어요. 안의 질은 평가하지 않으며, 그 과정의 태도를 봅니다."
- 기록되는 것: 토론방 대화, 결정 사항 선택, 기획안, AI 어시스턴트 요청 원문, 자료 열람.
- 평가는 누가 어떻게 하는가: 세션이 끝난 뒤 AI 평가 에이전트가 공개된 척도로 근거 메시지를 들어 요소별 수준을 판단하고, 담당자가 그것을 참고해 최종 평가한다.
- AI 어시스턴트(R7, 고정 문구): "AI가 평가 수준을 매기지 않으며, 요청·응답 기록은 담당자에게 사실로 제공됩니다."
- 합격·순위는 만들지 않는다. 리포트는 담당자가 평가할 때 보는 참고 자료다.
- 외부 도구 한 줄, 문의 창구, 동의하지 않을 때의 처리 한 줄씩.
- **표시 이름 입력**(D13-3): "토론방에서 보일 이름" 입력란 하나, 기본값은 입장 응답의 초대 이름, 수정 가능, 1~20자. 동의 요청에 함께 보낸다(`POST /s/{token}/consent {display_name}`, 응답에 `session_id`). AI 동료는 이 이름으로 "OO님"이라 부른다. 시작 뒤에는 바꾸지 않는다.

**대기 화면**
- "시작하면 바로 시간이 흐르고, 접속이 끊겨도 멈추지 않습니다."
- 팀 소개: AI 동료 세 명(강한결·윤하람·서지안)의 이름과 프로필 이미지, 그리고 내 표시 이름과 이니셜 아바타. 시작 전 `/state`의 `participants`로 그린다(시작 전 조회 허용, R5-19). "사람 팀원 역할을 맡은 AI입니다. 실제 동료처럼 대해 주세요." 유형·성향 설명은 없다.
- 진행 한 줄: "키워드 → 문제 상황 → 해결책을 함께 정하고, 마지막 14분에 기획안을 혼자 써서 제출합니다."(R3, 단계 10·18·18·14분)
- 레이아웃 그림 한 장(위 "레이아웃")과 영역별 한 줄: 상단 단계 진행바·남은 시간 / 가운데 토론방 / 우측 탭(결정 사항·자료·AI 어시스턴트·기획안).
- 시각 한 줄: "상단에는 이 단계의 남은 시간이, 메시지 옆에는 회의 속 시각(09:00~10:00)이 보입니다."
- "이 설명은 화면의 ? 버튼으로 다시 볼 수 있습니다."

## 지원자: 토론 세션

레이아웃은 위 "레이아웃". 상단 바, 가운데 토론방, 우측 패널(탭) 세 부분이다. 컴포넌트 이름은 [architecture/design-system.md](../architecture/design-system.md) 표.

**문구 원칙**: 화면 안내는 기능 설명만 한다(F9 원칙 유지). "동료 의견도 물어보세요", "누가 낸 아이디어인지 적어 주세요"처럼 평가 대상 행동을 유도하는 문구, 빈 상태 예시·추천 문구를 쓰지 않는다.

**시간 표기**(R7 한 줄 원칙): 상단 바와 시스템 안내는 실제 남은 시간("12:40 남음", "2분 남았어요")만 쓴다. 오피스 시각(`09:00 + t_min × 60 / session_minutes`, 분 단위 내림 "HH:MM")은 **메시지 타임스탬프에만** 쓴다. 결정 사항 결과 줄·마감 경고·접속 끊김 안내에는 오피스 시각을 넣지 않는다(안내 메시지 자체의 타임스탬프는 있음). 한 줄에 남은 시간과 오피스 시각을 함께 쓰지 않는다. 변환은 web이 한다(`/state`의 `session_minutes`·`office_start`·`office_end`). 관리자 리포트·기록 화면은 오피스 시각을 그대로 쓴다.

### 상단 바

- 반투명(vibrancy)을 쓰는 몇 안 되는 곳이다. 스크롤 아래 콘텐츠가 비치는 얇은 바, 아래 얇은 구분선.
- **단계 진행바(PhaseBar)**: 키워드 · 문제 상황 · 해결책 · 기획안 작성 4칸의 분절 표시. 지난 단계는 결과 아이콘 + 글자(합의/시간 초과), 현재 단계는 강조색 글자와 굵기, 다음 단계는 보조색. 칸에 시각을 붙이지 않는다.
- **남은 시간(Timer)**: "이 단계 12:40 남음"(오피스 시각을 붙이지 않음). `phase_remaining_seconds`를 로컬 카운트다운하고 WS `timer`로 보정한다. 숫자는 고정폭 숫자(tabular). 마감 2분 전(압축 비율)부터 warning 색, 깜빡임 없음. 일찍 확정하면 남은 시간이 다음 단계로 넘어가므로 다음 단계 시간은 `phase.changed`의 `phase_deadline_at`을 따른다.
- 오른쪽 끝 "?" 버튼: 대기 화면 설명을 대화 상자로 다시 보인다.

### 가운데: 토론방

- 채널은 토론방 하나다(DM·알림 채널 없음). 헤더에 "새 프로젝트 팀"과 참여자 목록(AI 동료 3명 프로필 이미지 + 지원자 이니셜 아바타, 이름은 마우스를 올리거나 목록을 펼치면).
- **메시지(MessageBubble)**: iMessage식 말풍선. 지원자 본인 메시지는 오른쪽 정렬, 강조색(시스템 블루) 바탕에 흰 글자. AI 동료 메시지는 왼쪽 정렬, 자리별 연한 틴트 바탕(`bubble-p1`·`bubble-p2`·`bubble-p3`, Apple 시스템 색의 틴트)에 본문 색 글자. AI 동료 말풍선 위에는 **이름**, 옆에는 **프로필 이미지**(원형 크롭·고정 크기, 아래 "프로필 이미지")를 둔다. 같은 사람의 연속 메시지는 말풍선을 붙여 묶고 이름·아바타는 묶음의 첫·끝에 한 번씩 보인다. 지원자 메시지는 오른쪽 정렬과 강조색으로 본인임이 분명하고, 묶음 첫 메시지 위에 작은 "나"를 둔다(지원자 이니셜 아바타는 참여자 목록과 헤더에 보인다). 색만으로 구분하지 않는다(D13-1).
- 시각은 메시지마다 붙이지 않고 묶음 사이 5분 이상 간격이나 단계 경계에 가운데 작은 회색 시각을 둔다(오피스 시각). 말풍선에 마우스를 올리면 그 메시지 시각.
- **시스템 안내(SystemNotice)**: 말풍선 없이 가운데 정렬 작은 회색 텍스트. 단계 시작("지금 할 일"과 남은 시간), 마감 임박, 칸 확정 결과, 자료 열림, 접속 끊김 구간.
- **입력 중 표시(TypingIndicator)**: WS `typing{participant, state}`로 그 자리의 말풍선 모양 점 세 개 + "윤하람님이 입력 중"을 목록 맨 아래에. 여러 명이면 "윤하람님, 서지안님이 입력 중". start 뒤 30초 안에 stop이 없으면 끈다(안전장치). 재접속 시 `/state.typing`으로 복원. 토큰 스트리밍은 없다(완성 문장이 한 번에 도착).
- **입력창**: 둥근 입력 필드와 보내기 버튼. `message.send{client_msg_id, content}`. `message.ack` 전에는 말풍선을 흐리게, ack 뒤 확정. ack은 메시지 저장 직후 의도 분류 전에 오므로 확정 표시가 AI 처리를 기다리지 않는다. 글자를 입력하는 동안 5초마다 `typing{start}`를 다시 보내고, 비우거나 전송하면 바로 `typing{stop}`. 입력이 멈추면 갱신도 멈추며 서버가 6초 뒤 만료한다(R5-9). 지원자가 입력 중인 동안 AI 동료 메시지는 게시되지 않는다. proposal 단계에서도 보낼 수 있다(AI 동료에게 묻기).
- 새 메시지 스크롤은 사용자가 맨 아래에 있을 때만 따라간다. 위를 보고 있으면 "새 메시지 n개" 버튼.
- 접속이 끊겼다 돌아오면 끊긴 구간을 시스템 안내로 남긴다("약 2분 동안 연결이 끊겼어요", `connection_gaps`, 평가 수준과 무관). 이어하기는 P0다(R7).

### 프로필 이미지 (D13-3)

- AI 동료는 페르소나마다 고정 프로필 이미지를 쓴다. 실존 인물 사진이 아닌 일관된 스타일의 일러스트·그래픽, 유형을 암시하지 않는 중립적 표정·스타일. 지원자는 이니셜 아바타.
- **지금 이미지는 임시(placeholder)이고 나중에 팀이 원하는 사진으로 교체한다.** 그래서 화면은 이미지 내용에 기대지 않는다:
  - 원천은 미션 카탈로그다. 페르소나의 `avatar` 필드(`scenarios/missions/<id>/personas.yaml`)가 정적 에셋 폴더(`scenarios/missions/<id>/assets/avatars/`)의 파일을 가리키고, api가 채용 건 생성 때 자리별 `avatar_url`로 고정해 내려준다. 교체는 파일과 경로만 바꾸면 된다(코드 변경 없음).
  - 화면은 `avatar_url`을 **원형 크롭·고정 크기**(20/28/36px)로 `object-fit: cover` 표시한다. 특정 비율·화풍·배경색에 의존하는 스타일(테두리 색 맞춤, 이미지 위 글자 등)을 쓰지 않는다.
  - 이미지가 없거나 로드에 실패하면 같은 크기의 이니셜 아바타(자리 색)로 대체한다.
  - 파일 이름과 URL은 중립 이름(`avatar-01.png` 등)이다. 유형 이름(`stubborn.png`)이 URL에 나오면 지원자에게 유형이 드러나므로 금지.
- 자리 틴트(말풍선)와 프로필 이미지는 별개다. 이미지를 바꿔도 틴트는 그대로다.

### 우측 패널: 탭

탭: [결정 사항] [자료] [AI 어시스턴트] [기획안]. 분절 컨트롤(segmented control) 모양. 탭을 바꿔도 각 탭의 스크롤·입력 중 내용은 유지한다. 기본 탭은 토론 단계에서 결정 사항, proposal 단계 시작 시 기획안으로 자동 전환한다.

**결정 사항 (ConsensusPanel)**
- 단계마다 정한 결과만 짧게 쌓인다: "키워드 · 물 · 합의", "문제 상황 · 가뭄으로 생활용수 제한 · 시간 초과". 오피스 시각은 넣지 않는다(R7). `resolution`은 아이콘 + 글자("합의"/"지원자 결정"/"시간 초과", 규칙은 [contracts/README.md](../contracts/README.md) "칸 결과 표시"), 정한 사람(`filled_by`)의 이름을 작게. 얇은 구분선으로 나눈 목록이며 줄마다 카드를 따로 두지 않는다.
- **후보안·지지 현황은 보이지 않는다**(D14). 토론은 채팅으로만 한다. `/state`에도 내려오지 않는다.
- 현재 단계의 정할 항목(SlotInput)만 입력과 [이걸로 정하기]가 있다. 칸 상태는 `empty | confirmed` 두 개뿐이고 입력 중인 값은 서버에 저장하지 않는다(`PUT slots`·`slot.filled` 없음, R5-5). [이걸로 정하기]는 확인 창(아래 "UX 결정" 2) 뒤 `POST .../confirm{value}`. 빈 값이면 버튼 비활성.
- keyword 항목은 후보 4개 분절 버튼 중 하나를 골라 옵션 키로 정한다. 방어용으로 422 `invalid_keyword`가 오면 항목 아래 한 줄로 보인다. problem·solution은 짧은 글 입력이다(서버는 LLM 없이 안과 연결).
- AI 동료가 정하거나 시간 초과로 정해지면 WS `slot.confirmed`로 항목이 잠기고 결과 줄이 쌓인다. 화면에만 있던 입력 값은 버린다. AI 합의 채우기는 칸 확정과 채운 자리의 공지("그럼 X로 정리할게요.")가 서버에서 함께 저장되므로 공지 `message.new`가 먼저 오고 이어서 `slot.confirmed` → `phase.changed` → `timer`가 온다. 공지 없이 칸만 잠기는 경우는 없다.
- 시간 초과 안내 문구(R7, api 고정 문장): "시간이 다 돼서 대화에서 가장 많이 모인 의견인 X로 할게요." 우선순위 자리(서지안)의 메시지로 온다.
- 오류: 409 `phase_not_open`·`slot_confirmed`면 `/state`를 다시 읽고 "이미 정해진 항목이에요" 한 줄.

**자료 (MaterialList + MarkdownViewer)**
- 키워드 확정 전: 잠금 아이콘과 한 줄 "키워드가 정해지면 자료가 열립니다." 목록 없음.
- WS `materials.opened{keyword, materials}`로 열린다. 시스템 안내 "「물」 자료가 열렸어요" 한 줄과 탭 배지.
- 목록은 제목만, 누르면 Markdown 뷰어(읽기 전용, 제목·목록·표·강조, 읽기 좋은 본문 폭). 열람은 `GET .../materials/{material_id}`가 기록한다. 423 `not_released`면 목록을 다시 읽는다.
- 확정 키워드에 자료가 없으면(정본상 막혀 있지만 방어) "이 키워드에는 준비된 자료가 없어요".

**AI 어시스턴트 (AssistantPanel)**
- 지원자 전용. 요청·응답 목록(말풍선 아님, 구분선으로 나누고 요청은 인용처럼 작게·응답은 본문), 응답은 제한 마크다운(굵게·기울임·목록·문단·코드만, 링크는 글자만, 이미지·제목·HTML은 글자로 강등), 입력 안내 "열린 자료에 대해 물어보세요", 인용 자료 제목 칩(어시스턴트가 도구로 찾은 자료, R5-13), 응답 대기 표시, 응답마다 "복사"(기획안에 직접 쓰지 않으므로 복사가 기본 동선). 반짝이·로봇 아이콘을 쓰지 않는다.
- 열린 자료만 검색한다는 한 줄 안내(기능 설명). 429 `assistant_limit`이면 "이 세션의 요청 한도를 다 썼어요".
- 토론방과 분리된 대화다. AI 동료는 이 대화를 보지 않는다.

**기획안 (ProposalEditor)**
- 템플릿 6칸: 키워드 · 문제 상황 · 해결책 · 근거 · 기대효과 · 아이디어 기여(필드 id `keyword`·`problem`·`solution`·`rationale`·`expected_effect`·`idea_credit`). 칸마다 제목과 textarea, 예시 문장 없음(결정 사항의 문제 상황·해결책 입력에는 형식 안내만: "누가 어떤 상황에서 무엇이 어려운지 한두 문장으로 적어요", "누가 무엇을 어떻게 하는지 한두 문장으로 적어요"). 문서처럼 넓은 여백.
- `idea_credit` 칸에는 무엇을 적는 칸인지만 중립적으로 한 줄 안내한다(R7): "이 기획에 반영된 의견과 그 의견을 낸 사람". 적으라고 권하거나 누가 냈는지 알려 주는 문구는 쓰지 않는다.
- 진행 중 언제든 쓸 수 있고(`PUT /sessions/{id}/proposal{sections, revision}`, 1초 디바운스, 마지막 저장 시각 표시), 제출은 proposal 단계에서만. 409 `conflict`(다른 탭)면 최신을 다시 읽고 "다른 창에서 고친 내용으로 바꿨어요" 토스트.
- proposal 단계 시작 때 앞 3칸이 비어 있으면 서버가 확정 칸 값으로 채운다(`/state` 재조회로 반영). 지원자가 고칠 수 있다.
- [제출]: 저장 대기분을 먼저 PUT → 빈 칸이 있으면 빈칸 경고 창(빈 칸 이름 목록, "비워 둔 칸이 있어요. 그대로 제출할까요?", [그대로 제출]·[돌아가서 쓰기]) → 확인 창("제출하면 수정할 수 없어요", [제출]·[취소]) → `POST .../proposal/submit`(경고 창을 거쳤으면 `blank_warning_shown: true`). 토론 단계에서는 [제출] 비활성 + "기획안 작성 단계에서 제출할 수 있어요".
- 화면은 우측 탭 안 6칸 세로 폼이다.

**새 소식 표시**: 토론방은 늘 보이므로 메시지 알림이 따로 없다. 우측 탭은 자료 열림·칸 확정에만 배지를 단다.

### 단계 전환

- WS 순서: `slot.confirmed` → `phase.changed{phase, previous_phase, reason}` → `timer` → (keyword였으면) `materials.opened` → 시스템 안내 `message.new`. AI 합의 채우기면 그 앞에 채운 자리의 공지 `message.new`가 온다.
- 진행바가 다음 칸으로 넘어가고, 결정 사항에 결과 줄이 쌓이고, 새 단계의 정할 항목이 열린다. 시간 초과(`reason: timeout`)면 결과 줄과 진행바 아이콘이 "시간 초과"로 보인다.
- 연출은 진행바 칸 이동 + 결과 줄 짧은 강조 + 가운데 회색 시스템 안내뿐이다.

### 종료 → 디브리핑

- 제출 성공 또는 WS `session.ended{reason}`을 받으면(submitted·timeout이면 세션은 이미 completed) 입력창·칸·기획안·어시스턴트를 모두 잠그고 상단에 **[나가기]** 버튼을 띄운다. 누르면 디브리핑으로 화면만 이동한다(API 호출 없음).
- 자동 제출(`reason: timeout`, `proposals.auto_submitted`): 같은 흐름이고 디브리핑 머리에 "시간이 끝나 지금 상태로 제출됐어요" 한 줄.
- `failed`: "세션이 중단됐어요. 담당자가 새 링크를 보낼 수 있습니다." `cancelled`: 취소 안내.
- [나가기]를 누르지 않고 이탈하면 재접속 시 `GET /s/{token}`이 completed라 바로 디브리핑으로 간다.
- 재연결: WS가 끊기면 3초 후 재연결하고 `/sessions/{id}/state`로 전체 갱신(메시지·칸·기획안·자료·어시스턴트·typing·active_runs). 연결 중에도 프레임 봉투의 세션 단위 `seq`가 비면(앞 번호 누락) 같은 방식으로 `/state`를 다시 읽는다(R5-10). close 4401이면 `/s/{token}/resume`으로 JWT 재발급, 4403·4000은 재연결하지 않는다(4000은 "다른 창에서 열렸어요").

### 디브리핑

`GET /sessions/{id}/debrief`(세션 JWT 또는 debrief_token). 큰 제목과 넓은 여백의 한 열 문서.
- "수고하셨습니다" 다음 첫 문장(R1, 고정): "같은 채용 건의 모든 지원자가 같은 장면을 겪었고, 정답 없이 반응을 봅니다." 바로 아래 "평가 결과는 보여 드리지 않습니다."(`scoring_notice` 첫 문장)와 이의 제기 경로(문의 창구와 절차 한 줄). 설문 제출 확인은 성공 표시(success-soft 면·체크 아이콘). 내 발언 돌아보기·제출한 기획안은 접힘 구간.
- 실제 발동한 카드마다 고정 설명 문장(`cards[].description`, 원천은 `observations`)과 관련 평가 요소 이름·"이렇게 봅니다" 한 줄. 척도 세부·차원 앵커는 보이지 않는다.
- 내 발언 돌아보기(R7): 토론 단계(키워드·문제 상황·해결책)마다 가장 긴 본인 발언 1개, 최대 3개를 읽기 전용으로 보인다(`my_messages`, 선택은 api). 평가·설명 없이 원문과 메시지 시각만.
- AI 동료 소개: 자리별 이름·프로필 이미지와 성향 설명(`seats[].persona_description`). 이때 처음으로 유형이 드러난다.
- 평가 결과를 보여 주지 않는 이유(`scoring_notice`), 기업이 보는 것(대화·어시스턴트 요청 원문, 제출 기획안), 끊긴 구간이 있었다면 담당자에게 알리라는 안내, 기록 보관 90일, 이의 제기·문의 창구.
- 제출한 기획안 읽기 전용 열람과 복사(종료 후 7일, `view_until`).
- 종료 설문 2문항(자연스러웠나 `natural` / 공정했나 `fair`, 1~5)과 자유 의견 한 칸(R7). 모두 건너뛰기 가능, 한 번만.
- 세션 실패면 카드·성향·기획안 없이 중단·재응시 안내만.

## 관리자: 채용 건 생성

- 입력은 이름과 세션 길이뿐이다. **요소 선택 UI는 없다**(R2): 모든 채용 건이 같은 5요소·같은 척도를 쓴다.
- 세션 길이: 60분(기본) / 15분(데모, R3), 분절 컨트롤. 미션은 MVP 고정 1개라 선택 UI 없음.
- 보는 요소 안내(읽기 전용, `GET /admin/catalog`의 elements): 설득/논리력, 경청/존중, 배려/포용, 수용/유연성, 정직/공정. 항목마다 이름·한 줄 뜻·"이렇게 봅니다" 2~3줄, 얇은 구분선 목록. 체크·스위치 없음. **페르소나 유형·카드 장면·차원 앵커는 보이지 않는다.**
- 안내 줄: "모든 채용 건이 같은 요소와 같은 척도로 기록됩니다." 아래 "샘플 리포트 보기".
- 생성 응답의 `seats`(이름)와 `keywords`(후보 4개)는 확인용으로 이름·키워드만 보인다. 유형은 리포트에서 본다.

## 관리자: 지원자 목록·초대

- 초대 폼: 별칭(설명 "지원자에게 이 이름으로 안내되고 세션과 리포트에 남습니다"), 이메일. 같은 채용 건 중복 별칭은 제출 전에 막는다. 응답의 `invite_url`·`notice_text` 복사 버튼(발송하지 않음).
- 링크 재발급(`POST /admin/sessions/{id}/reissue`, R5-20)은 시작 전·만료 행에서: 같은 세션·같은 별칭으로 토큰과 만료만 바꾸고 새 `invite_url`을 복사한다. 재응시 초대(previous_session_id, 새 세션)는 세션 실패·취소 행에서만. 두 버튼의 설명을 한 줄씩 구분해 둔다.
- 상태 묶음(필터 겸용, `display_group`): 대기 / 진행(현재 단계 `phase`, 시작·종료 예정 시각) / 검토 필요 / 완료 / 문제. 목록은 표(얇은 행 구분선)이며 행마다 카드를 두지 않는다.
- 행마다 마지막 활동 시각·메시지 수·삭제 예정일(`purge_at` = 종료 시각 `ended_at` + 90일, 완료·실패·취소 모두). 실패 행은 담당자 행동 안내(`next_action`).
- 평가는 **요소별 수준 칩**("설득 3"처럼 요소 짧은 이름 + 최종 수준 1~5, 기록 없음이면 "—")과 **확신도 low 차원 수**("근거 약함 2"), 출처(자동/담당자 조정). 합계·평균 없음, **수준 정렬·순위 없음**(표 정렬 키로 쓰지 않는다).

## 관리자: 리포트 화면

D13-2 톤: 흰 바탕, 한 열 문서처럼 읽히는 구조, 큰 제목과 분명한 위계, 얇은 구분선. 색은 수준·확신도 칩과 참여자 표시에만 쓰고 카드만 반복되는 대시보드로 만들지 않는다. 채용 관계자가 바로 읽을 문장으로 쓰고 코드 id는 화면에 보이지 않는다(차원은 [product/rubric.md](rubric.md)의 한국어 이름으로). **총점·합계는 어디에도 없다.**

**머리**
- 단계 배지(검토 대기 / 확정 중 / 검토 완료), 검토자 이름, 삭제 예정일, "인쇄".
- 고정 문구: "이 리포트는 담당자가 평가할 때 보는 참고 자료입니다. 수준은 세션 뒤 AI 평가 에이전트가 공개된 척도로 근거를 들어 판단한 값이며, 담당자가 원문을 보고 차원 단위로 조정해 최종 평가합니다. 합격·불합격·순위는 판정하지 않습니다."
- 설계된 장면 표시(R1, 담당자용 고정 문구): "동료의 반대·압박·머뭇거림 같은 장면은 같은 채용 건의 모든 지원자에게 같게 설계된 장면입니다. 지원자 안이 채택되지 않은 것은 설계의 결과일 수 있습니다." 타임라인의 카드 표식과 요소 섹션의 "관련 카드 장면"에도 "설계된 장면" 칩을 붙인다.
- 참여자: 지원자 별칭(표시 이름이 다르면 함께), 자리별 이름·프로필 이미지와 유형(`seats[].persona_type`의 한국어 이름).
- **요약표**: 요소마다 한 행. 요소 이름, **"수준 N (1~5)"**(`elements[].level`, null이면 기록 없음 표시 문장), 서술 1~2줄(`summary`), 기록 없음 차원 수(`no_record_count`/`dimension_count`), 확신도 low 차원 수, 담당자 조정 값(`adjusted_level`)이 있으면 자동 값 옆에 "담당자 조정됨"과 함께. 합계 행 없음. 행을 누르면 해당 요소 섹션으로.

**① 토론 흐름 (타임라인)**
- 가로 단계 띠: 단계별 칸 결과(`slots[]`: 값, 합의/시간 초과, 채운 사람, 확정 시각), 확정 시점 지지 현황(`support`: 안별 지지자 이름), 확정 안의 최초 제안자(`first_proposer`).
- 카드 발동 표시(`cards[]`: 단계, 발동 시각, 관찰 창, 장면 한 줄(`scene`, 카드의 고정 문장), "설계된 장면" 칩, 미발생이면 "이벤트 미발생", 발동했지만 담당 동료 일부만 전달했으면(`delivered=false`) "일부 동료만 전달됨"). 누르면 그 요소 섹션으로.
- 접속 끊김 구간(`connection_gaps`)을 회색 띠로.

**② 요소 섹션**
- 요소마다 소제목·"수준 N (1~5)"·서술. 차원 3~4개(`dimensions[]` 중 그 요소)가 접힌 상태로, 소제목 줄에 차원별 수준 칩과 확신도 표시만 미리 보인다.
- **차원(DimensionRow)**을 펼치면: 차원 이름과 정의 한 줄, **수준 칩**("수준 4", 기록 없음이면 사유 문장), **확신도**(높음/보통/낮음, 아이콘 + 글자), 판단 이유(`rationale`), 관련 카드 장면, 담당자 참고 문구(해당 수준의 앵커 행), 근거 목록. 확신도 `low`면 차원 옆에 **"근거 약함, 원문 확인 권장"**을 warning 톤 글자로 붙인다(색만으로 표시하지 않음).
- **근거(EvidenceItem)**: 참조 종류별로 보인다. `msg:`는 오피스 시각·단계·원문 인용(토론방과 같은 말풍선 색·이름)·자발/초대 후(`origin`). `slot:`은 단계·값·합의/시간 초과·채운 사람·지지 현황. `proposal:`은 기획안 필드 이름과 발췌. `contribution:`과 AI 동료 메시지는 "맥락" 칩을 달고 흐리게(근거 개수에 들지 않음). **근거를 누르면 그 자리에서 원문과 앞뒤 맥락(앞 5·뒤 3 메시지)이 펼쳐지고** 근거 메시지는 accent-soft로 강조한다. 근거마다 "기록에서 보기"(`record_ref` → `/admin/sessions/{id}/record#<id>` 하이라이트). 보조 장면 근거는 `rationale`에 표시된 대로 "보조 장면" 칩.
- **담당자 조정(draft에서만, 차원 단위)**: 차원마다 [조정] → 수준 선택(1~5 분절 컨트롤) 또는 "기록 없음"(사유 선택)과 **메모(필수)**. 메모가 비면 저장 비활성. 조정하면 자동 값(회색)과 담당자 값·메모가 나란히 보이고, 요소 수준은 조정된 차원으로 다시 계산해 "담당자 조정됨"을 붙인다. 자동 서술은 그대로 둔다.
- 화면에 보이는 말은 "차원" 대신 **"세부 행동"**이다(결정 A4, 평가 문장 속 "차원"도 화면에서 바꿔 보인다). 머리에 접힌 **용어 설명**(세부 행동, 수준 1~5, 확신도, 장면 없음·선결정·반응 없음·판단 보류, 설계된 장면)을 둔다.
- 기록 없음은 **상태 칩**(장면 없음 ∣ 반응 없음 ∣ 판단 보류, 결정 A3)과 사유 문장으로 보인다([product/rubric.md](rubric.md) 2.3·5장). 요약표의 기록 없음 칸은 상태별 개수를 함께 보이고, 조정의 사유 선택은 상태별로 묶는다. 지원자 안이 채택되면 수용의 결정 뒤 세부 행동(결과 승복·다음 단계 기여)은 `not_applicable`이고 결정 전 세부 행동은 카드 장면으로 판단한다(결정 A5). 카드가 선결정으로 생기지 않았으면 타임라인과 관련 카드 장면에 "이벤트 미발생" 대신 "선결정"을 보인다.

| 사유 | 상태 | 화면 문장 |
|---|---|---|
| no_activity | 반응 없음 | 지원자 활동 없음 |
| evaluate_failed | 판단 보류 | 판단 보류 · 근거 부족 — 원문 기록 확인 권장 |
| not_applicable | 장면 없음 | 해당 없음 |
| preempted | 장면 없음 | 선결정 · 카드 전에 지원자가 칸을 확정 |
| event_not_fired | 장면 없음 | 이벤트 미발생 |
| auto_submitted_blank | 반응 없음 | 자동 제출로 기여 칸 미작성 |

- 정직/공정 섹션: 기여 대조표(`contribution_check`: 안별 실제 최초 제안자 / 기획안에 적힌 기여자)와 제출 기획안의 `idea_credit` 원문을 나란히.

**③ 사실 지표**: `facts`를 표로. 발언 수(단계별), 자발/초대 후 수와 비율, 응답 간격 중앙값, 의도별 수 등([product/rubric.md](rubric.md) 6장 지표의 한국어 표기). "수준 판단에 쓰인 참고 기록이며 이것만으로 수준을 정하지 않습니다" 한 줄.

**④ 제출 기획안**: 6칸 읽기 전용, 제출 시각, 자동 제출이면 "시간 종료로 자동 제출".

**⑤ AI 활용**: "판단 기준 없음, 면접 확인용". 요청·응답·인용 자료를 시간순으로만. 분류·비율 없음. 각 호출에 "기록에서 보기".

**검토 완료**
- 하단 검토자 이름(필수)과 [검토 완료]. 확인 창 "검토 완료 후 수준은 바꿀 수 없습니다. 메모는 계속 추가할 수 있습니다." → `POST /review{reviewer_name, adjustments: [{dimension_id, level, no_record_reason?, memo}]}`(R5-16) → "확정 중…" → 폴링으로 final이면 검토 시각·검토자. 검증 오류(422, 이름·메모 비어 있음 등)는 해당 입력 아래 한 줄, 409 `already_reviewed`면 최신 리포트를 다시 읽는다.
- 확정 실패 시 "조정은 저장되어 있습니다. 확정만 다시 시도합니다."와 재시도.
- final에서는 값 입력이 잠기고 리포트 메모 추가만(`POST .../report/notes`).

**인쇄**: 인쇄 CSS로 브라우저 PDF(항상 라이트). 접힌 차원 전부 펼침(근거 앞뒤 맥락은 근거 메시지만), 토글·버튼·링크 숨김, 머리 문구·검토자·검토 시각 포함.

## 관리자: 전체 기록 화면

- `GET /admin/sessions/{id}/record`의 한 타임라인: 종류 `message`·`slot`·`phase`·`assistant_call`·`material_view`·`proposal_submit`·`connection_gap`. 줄마다 오피스 시각·종류 칩·주체(이름·프로필 이미지 또는 이니셜)·요약. 메시지는 토론방과 같은 참여자 색·이름.
- 필터: 종류, 주체(지원자·AI 동료별·시스템), 단계.
- 리포트에서 들어오면 `#<record_ref id>` 줄로 스크롤하고 accent-soft 하이라이트, 상단 "리포트로 돌아가기". 읽기 전용, 인쇄 CSS.

## UX 결정 (2026-10-21)

사용자가 시안 중 추천안으로 확정한 결정이다. 이유와 기각한 대안은 [decisions.md](../decisions.md) "G-U UX 결정".

| 항목 | 결정 | 이유 |
|---|---|---|
| 1. 혼자 확정 | 합의 여부와 상관없이 늘 같은 흐름([이걸로 정하기] → 확인 창). 지지 현황은 화면에 보이지 않고 기록에만 남는다 | 화면이 합의를 판정하지 않는다. 확정 행위 자체는 평가 에이전트의 `flex_decision_respect`(결정 존중) 차원이 판단하고, `flex_acceptance`는 결정 뒤 행동만 본다(R5-17) |
| 2. 오클릭 방지 | 확인 창 하나("이걸로 정하면 다음 단계로 넘어가요", [이걸로 정하기]·[취소]) | 가장 단순하고 1번 흐름과 같은 창을 쓴다 |
| 3. keyword 항목 입력 | 후보 4개 분절 버튼 + [이걸로 정하기] | 후보 밖 값이 생기지 않아 422 안내가 필요 없다 |
| 4. 단계 전환 연출 | 진행바 칸 이동 + 결정 사항 결과 줄 짧은 강조 + 가운데 회색 시스템 안내 | 토론 흐름을 끊지 않는 절제된 전환 |
| 5. 기획안 단계 진입 | 우측 탭이 기획안으로 자동 전환 | 레이아웃을 바꾸지 않고 할 일만 앞으로 가져온다 |
| 6. 기획안 작성 화면 | 우측 탭 안 6칸 세로 폼 | 토론방을 보며 쓸 수 있고 구조가 단순하다 |
| 7. 기업 리포트 구조 | 한 열 문서: 요약표(요소별 "수준 N (1~5)"·확신도 low 차원 수, 총점 없음) → 타임라인 → 요소 섹션(접힘) → 사실 지표 → 기획안 → AI 활용 | 위에서 아래로 읽히는 문서가 인쇄·검토에 맞다 |
| 8. 리포트 근거 보기 | 차원 아래 근거 자리에서 원문과 앞 5·뒤 3 맥락을 펼침. 차원 줄에는 수준 칩·확신도가 함께 보인다 | 수준과 근거를 같은 자리에서 대조할 수 있다 |
| 9. 라이트·다크 | 시스템 설정(`prefers-color-scheme`)만 따름 | 토글 없이도 두 테마를 지원한다 |
| 10. AI 동료 틴트 | 자리 고정(p1 오렌지·p2 그린·p3 퍼플) | 자리는 페르소나 유형과 무관하게 배정되므로 색이 유형을 드러내지 않는다 |
