단계별 화면 · Playwright e2e

단계마다 시작점을 만들고 그 단계만 확인합니다

음성 회의 화면 두 장은 10-26 test-voice 캡처(발표자 보기)이고, 나머지 영상과 스크린샷은 10-26 텍스트 모드(VOICE_ENABLED=0) 기록입니다. 해결책의 AI 합의 채우기는 10-26에도 실패해 그 영상과 "합의 채움" 한 장만 10-22 기록(이전 화면)을 둡니다. 지금 토론방은 채팅 대신 음성 회의 화면이지만 결정 사항 · 기획안 · 디브리핑 · 관리자 리포트의 흐름은 같습니다. 스크린샷은 움직임 줄이기 설정으로, 단계 전환 장면이 지나간 뒤에 찍었습니다. 처음부터 15분을 다 돌지 않고, 단계 시드(scenarios/e2e/stages/*.yaml)로 그 단계 직전 상태의 세션을 만든 뒤 시간을 당겨 카드·마감·침묵을 일으킵니다. 결정적 LLM 모드라 동료 문장이 매번 같습니다. 영상은 실제 속도, 스크린샷은 눌러서 크게 봅니다.

음성 회의 test-voice

내 차례에 [발언하기]를 누르면 녹음이 시작되고 내 칸이 큰 칸으로 바뀌며 남은 발언 시간과 [발언 완료]가 보입니다. 받아 적은 글은 지원자에게 보이지 않고 그대로 제출되며 "전달했어요"만 잠깐 보입니다. 동료 발언은 실시간 자막과 방금 한 말 한 문장만 보이고, 칸마다 상태 배지가 붙습니다.

바뀐 것

  • 토론방이 채팅 대신 턴 기반 음성 회의가 됐습니다. 검증된 최종 발언만 Azure F0 TTS로 순서대로 재생하고, 실제 재생 종료를 확인한 뒤 지원자 차례를 엽니다.
  • 발표자 보기: 실제 말하는 사람을 큰 칸으로, 동료 발언은 실시간 자막과 방금 한 말 한 문장만 보이고 기록 목록은 없습니다.
  • 받아 적은 글은 지원자가 보거나 고치지 않고 그대로 제출됩니다. 서버도 받아 적은 글과 다른 제출을 voice_payload_mismatch로 거부합니다.
  • 일반 · 손들기 · 강제 차례 모두 지원자가 [발언하기]로 시작하고, 20초 안에 시작하지 않으면 동료 차례로 넘어갑니다.
  • 강제 차례는 그 단계에 발언이 없을 때 단계가 절반 넘게 지난 뒤 마감 전에 한 번 옵니다.
  • 빈 인식 · 500자 초과는 다시 말하기를 안내하고, 500자 초과의 다시 말하기는 다시 녹음 1회와 따로 차례당 2회까지 받습니다.
  • Azure 이전에 쓰던 웹 서버의 OpenAI 음성 경로와 개인 키를 읽던 코드를 지웠습니다. 키는 제한 키 허용 목록 하나로 고릅니다.
  • 기획안 단계에는 새 음성 차례가 없고 어시스턴트만 돕습니다.

남은 한계

  • 동료의 오인용 약 11%. 제한 키로 쓸 수 있는 판정 모델 중 보정을 통과한 것이 없어 후속 이슈(#17)로 둡니다.
